# v0.6.3 회전 행과 잘린 입력 처리

사용자의 새 GPU 로그에서 v0.6.2는 재분할 후 `<UNK>`도 거부했다. 검사 우회는 막혔지만 `[0,0,648,41]`의 잘못된 행을 더 작은 조각으로 계속 읽으므로 원인은 남아 있었다. 원래 612×221px 크롭에서 일부 획이 이미 사라졌고, 회전 후 231·246px 분할선은 실제 글줄을 가로질렀다.

## 행 구성

회전각은 기존처럼 검출 마스크 안에서 추정한다. 행은 원본 RGB에서 연결된 글자 성분의 높이·기준선·가로 반복으로 검증한다. 검출 지지가 없는 별도 글줄 후보는 완료된 원문으로 간주하지 않는다. 투영 봉우리의 위·아래가 다른 행으로 나뉘어도 RGB 글자 성분이 연결되어 있으면 글자 가운데에 분할선을 만들지 않는다. 어두운 글자·밝은 글자를 각각 분석하고, 검출 마스크가 지지하는 쪽을 선택한다.

분석은 긴 변 1024px 이하로 샘플링하고 성분 수 32768·행 수 32, 기존 원본/회전 래스터 한도를 유지한다. 이것은 글줄 기하 검사이며 글자의 의미·OCR 정확도 판단이 아니다.

회전한 원본 크롭의 유효 픽셀 영역도 함께 계산한다. 글자 후보가 이 영역의 경계에서 잘린 흔적을 여러 독립 성분으로 보이면 `source_crop_cuts_glyphs`로 기록한다. 속이 빈 장식의 외곽·내곽을 서로 다른 잘린 글자로 중복 계산하지 않는다. 그림의 긴 선은 글자 높이와 비교해 제외한다. 모호한 경우 검수로 남을 수 있다.

## 기본 동작과 확인 위치

통합 08의 `④ OCR 전 단·회전 보정 · 잘린 글자 원본 보존·검수` 노드에서 `geometry_policy`를 선택한다.

- `preserve_review` 기본값: 확인되지 않은 영역과 여백이 겹치는 이웃을 먼저 제외한다. 다른 안전한 영역은 계속 처리한다. 해당 영역은 OCR·번역·제거·새 식자를 수행하지 않고 원본 픽셀을 보존한다.
- `strict`: OCR 실행 전에 영역 ID·크롭 좌표·기하 오류를 포함해 중단한다.

이 검사는 `auto_deskew=true`에서 동작한다. 기존 수동 노드의 false 기본값은 바뀌지 않았다. 회전이 불필요한 입력·검출 지지 부재의 기존 경로도 유지한다. 검사 실패를 피하려고 품질 검사를 끄거나 미인식 표시를 삭제할 필요는 없다.

모든 선택 영역이 보존되면 원본 페이지를 출력한다. 빈 페이지로 확정하거나 완료된 번역으로 기록하지 않는다. 폴더 상태는 `needs_review`, 이유는 `unverified_ocr_geometry`다. 일부 영역만 처리된 페이지도 검수 상태를 유지한다. 기존 원본 보호 계약을 재사용하므로 마스크 확대·단색 채우기·생성 제거·식자가 보존 영역에 다시 접근하지 않는다.

OCR manifest 및 기존 `미리보기 아무거나`의 `ocr_geometry_review`에서 영역 ID, crop/edit bbox, `analysis.row_validation.bands_pixels`, `clipped_source_rows`, 보존 ID를 확인한다. 잘린 성분 좌표는 `rectified_crop_pixels` 좌표계다. 편집 계획 미리보기에는 원본 보존 영역이 표시된다.

업데이트 후 ComfyUI를 재시작하고 최신 통합 08을 가져오면 정책 위젯이 보인다. 이전 08에서도 생략된 정책의 런타임 기본값은 같다. v0.6.2 그래프와 새 기본 그래프의 프로젝트 fingerprint는 실제로 동일한 `bda5fb18693d6ba89b5f6ebd9182de8bc69b3f75e323b346cd7ba48fdab24c31`이었다. 같은 프로젝트에서 실패 재시도를 사용할 수 있다. 이미 완료된 페이지를 자동 재처리하지는 않는다.

## 실제 이미지·CPU 확인

이전 실제 CPU 검출 결과의 .10 진단 후보 마스크를 사용해 같은 원본 크롭을 분석했다. 사용자 GPU 마스크 자체를 받은 것은 아니다. -13.5° 보정과 5개 글줄 후보를 얻었고, 아래 두 글줄에서 각각 5개·2개의 잘린 성분 묶음을 확인했다. 새 경계는 `[0,98,140,197,266,359]`로, 기존의 15px 조각을 만들지 않는다.

이 5개 입력을 검증된 Hayai 가중치로 CPU float32·4스레드에서 진단했다. 원문이 잘린 입력이므로 아래 결과를 실제 번역에 채택하지 않았다.

| 입력 | 실제 OCR 응답 |
| --- | --- |
| 제목 | `MY PROFILE` |
| 이름 | `(わたし)の名前はカーマ!` |
| 클래스 | `クラスはアサシンのサーヴァントなんだ☆` |
| 이전 15px 조각 대신 69px 글줄 | `Buster. Arts-Quick)` |
| 아래 잘린 문장 | `※※就象(水)きなり` |

글줄을 합치면 일부 인식이 나아지지만 없는 획은 복원되지 않았다. 실제 페이지 픽셀·이전 CPU 검출 마스크를 `MangaRegionCrops → 적응형 OCR → 집계 → 번역 → 편집 계획 → 제거 조립`에 통과시킨 확인에서는 OCR/번역이 생략되고 제거 타일 0개, 최종 픽셀 전체가 원본과 동일했다. 모델 대역으로 이 결과를 만들어낸 것은 아니며, 보호 경로에서는 모델을 부르지 않았다. 실제 Hayai 진단 5건과 보호 경로의 무호출 검사는 별도다.

## 남은 한계

이 변경은 잘못된 행 경계와 불확실한 원문을 무조건 실행하는 경로를 고친다. 현재 카드에서는 유일한 선택 영역 r1이 보존되어 페이지가 번역되지 않은 채 검수로 남는다. 이 결과를 OCR 정확도 개선 완료라고 부르지 않는다. 잘린 본문 영역을 온전히 재구성하려면 검출 후보·원본 문맥·다른 영역의 소유권을 함께 검증해야 한다. 영역을 무작정 확대하거나 검출 임계값을 낮추지 않았다.
