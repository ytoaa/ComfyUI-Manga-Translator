# v0.3.1 — 효과음 경계 복구와 OCR 입력 개선

사용자 보고의 두 실패를 분리했다. 1086×1448 페이지에서는 효과음으로 분류된 조각
`[198.94,919.36,576,1088]`의 지원율이 53.61%에 머물러 전체 검출이 중단됐다.
첨부 이미지를 눈으로 대조하면 해당 위치는 가방/옷으로, 오검출이 의심된다.
원시 마스크·전체 검출 응답 없이 모델의 오검출 원인까지 확정한 것은 아니다.
1600×640 설명 이미지에서는 경계 복구가 통과했지만 OCR 누락과 짧은 반복이 번역에 전달됐다.

## 적용

1. 저장소를 업데이트하고 ComfyUI를 재시작한다.
2. `lettering/example_workflows/08-integrated-tiled-cleanup-lettering.json`을 새로 가져온다.
3. 원본 이미지, 모델, 기존 번역 서버를 선택한다. 영역 ID가 바뀔 수 있으므로 이전 ID별 수동 설정은 재확인한다.

기존 저장 그래프를 열기만 하면 새 연결과 기본값이 적용되지 않는다. 노드 타입과 기존 출력 0은 유지했다.
추가 커스텀 노드 없이 기존 노드 내부를 수정하고 미리보기는 기본 PreviewImage를 쓴다.

## 효과음과 경계 복구

검출 노드에 `include_sfx`를 추가했다. 새 08은 검출·영역 선택·마스크의 세 설정을 모두 false로 둔다.
효과음이 필요하면 세 곳을 모두 true로 변경한다. 검출 노드에서 제외한 효과음은 뒤에서 되살릴 수 없다.
제외는 전체/타일/복구 응답에 모두 적용되므로, 원치 않는 효과음 조각이 본문을 중단하거나 제거 마스크에 섞이지 않는다.
이전 그래프의 검출 노드 기본값은 true로 유지해 기존 효과음 사용을 조용히 끄지 않는다.

포함한 글자/효과음의 98% 지원 기준과 복구 한도는 유지한다.
효과음을 켰을 때 해결되지 않은 오검출을 자동으로 비문자로 판정해 버리는 기능은 없다.
오류에는 조각의 label/score도 기록한다. 제외 건수는 boundary_recovery 진단에 기록한다.

## OCR 입력과 품질 검사

08은 `base_patches=256`, `small_text_patches=512`, `tight_crop=false`,
`line_split=true`, `split_long_lines=true`, `quality_guard=true`다.
기존 512/1024 자동 배정의 실측 우월성이 확인되지 않아 더 작은 비교 기준으로 변경했다.
새 설정이 모든 이미지에서 더 정확하다는 주장은 아니다. 세 patch budget은 계속 수동 비교할 수 있다.

긴 가로 행은 대비 기반 전경을 구한 뒤 빈 열 간격에서 분할한다.
공백만 있는 여백을 별도 OCR 조각으로 만들지 않으며 분할 이미지의 픽셀은 겹치거나 누락되지 않는다.
세로 입력, 충분한 간격이 없는 입력, 한도를 넘는 계획은 원래 행을 유지한다.
최대 행 수는 32, 행당 조각은 16, 영역당 총 조각은 128이다.
빈 열은 의미상 글자 경계를 보장하지 않는다. 장식·복잡한 한자·연결 필기에서는 직접 검수하거나 분할을 끈다.
조각 간 CJK 문자열은 중복 제거 없이 연결하고 라틴 영숫자 경계에는 공백을 넣으므로 혼합 글씨도 검수 대상이다.

짧은 주기 반복과, 전경의 독립된 세로 띠 수에 비해 지나치게 짧은 인식 결과를 의심한다.
의심되면 같은 이미지에서 patch budget을 256 또는 512로 바꿔 한 번 재시도한다.
계속 의심되면 원문 수집/번역에 전달하지 않는다. 어댑터의 기존 장기 반복 재시도는 별도로 최대 한 번이다.
반복 대사·장식 글씨의 정상 결과를 의심할 수 있고, 자연스럽게 틀린 OCR은 통과할 수 있다.
이 검사는 신뢰도 점수나 인식 정확도 검증이 아니다. 무조건 긴 결과를 고르거나 번역 LLM으로 원문을 추측하지 않는다.

OCR 노드의 추가 출력은 `ocr_report_json`과 `ocr_inputs`다.
성공한 원문 JSON의 각 영역에 `ocr_diagnostics`를 저장하고 번역 JSON에도 보존한다.
원본 영역 크기, 행/조각 수, 행 내부 조각 좌표, 실제 NaFlex 입력 크기, patch budget, 재시도 사유가 포함된다.
전체 인식 문자열은 기존 source 필드에 있고 로그에는 자동으로 덤프하지 않는다.

`검수 · 실제 OCR 입력 행/조각`은 성공한 OCR 입력을 보여준다.
실패 시에는 출력이 반환되지 않아 이 미리보기도 생성되지 않을 수 있다.
`검수 · OCR 전 원본 영역 크롭`만 출력 대상으로 실행하면 OCR 없이 크롭을 확인할 수 있다.
진단 목적으로 quality_guard를 끄면 잘못된 원문도 뒤 단계로 전달될 수 있으므로 OCR 출력만 검수한다.

## 문단 복원

08의 `merge_adjacent_lines=true`는 가까운 가로 행 중 높이가 비슷하고 왼쪽이 정렬된 경우를 묶는다.
서로 다른/애매한 말풍선, 효과음, 마스크에서 이미 여러 줄인 영역은 합치지 않는다.
그룹의 커진 높이가 아니라 원래 행끼리 비교하므로 문단이 커질수록 허용 간격이 늘지 않는다.
제공된 r4/r5의 픽셀 박스는 하나로 묶고 그 위/아래 문단은 분리하는 회귀 검사를 추가했다.
원래 행 좌표는 `line_bboxes_pixels`로 남긴다. 검출 마스크가 없으면 다중 행 구분 근거가 부족할 수 있다.
이는 의미론적 문단 분석이 아니다. 오묶음은 해당 옵션을 끄고 확인한다.

## 검증 범위

실제 사용자 이미지에 대한 RF-DETR/Hayai GPU 추론을 실행하지 않았다.
보고된 좌표와 반복 문자열, 합성 픽셀, 모델 대역을 사용한 CPU 검증이다.
경계 처리, 분할의 픽셀 보존, 재시도/실패 전파, JSON/ID/워크플로 연결과 패키지 import를 검증한다.
검출·인식·번역 정확도, Qwen 잔점 제거, 브라우저 실행, 최종 시각 품질은 사용자 환경 재실행으로 확인해야 한다.
