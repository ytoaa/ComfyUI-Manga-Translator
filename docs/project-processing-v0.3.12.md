# 경계 시뮬레이션과 폴더 프로젝트 — v0.3.12

08 하나를 유지하면서 프로젝트 폴더를 페이지별로 처리하는 실행기를 추가했다.
새 이미지 로더/반복 실행 커스텀 노드나 별도 10번 워크플로우를 추가하지 않는다.
설정한 08 API 그래프를 기존 ComfyUI 서버에 한 페이지씩 제출한다. 모델은 ComfyUI 안에 유지된다.
이미지 크기가 달라도 서로 다른 작업으로 처리하며, 09의 고정 수동 영역을 책 전체에 재사용하지 않는다.
입력 후보는 PNG/JPEG/WebP/BMP/TIFF/GIF 파일이며 다중 프레임은 명시적 오류로 남긴다.

## 실행

업데이트 후 ComfyUI를 재시작한다. GUI에서 모델·번역 서버·글자 선택·식자 옵션을 설정한 08을
**API 형식 JSON**으로 저장한다. 일반 GUI 워크플로우 JSON은 실행기에서 거부한다.
기본 예제의 설정이 실제 환경에 맞으면 --workflow를 생략할 수 있다.

ComfyUI 환경의 Python과 저장소 루트를 사용한다. 아래 입력/출력 경로는 사용자의 프로젝트에 맞춘다.
출력 폴더를 입력 폴더 안에 두면 재귀적으로 결과를 다시 읽을 수 있으므로 시작 전에 거부한다.

```bash
python3 tools/run_project.py \
  --input /media/tosol/ng/manga/book01 \
  --project /media/tosol/ng/manga-results/book01 \
  --workflow /media/tosol/ng/workflows/book08.api.json \
  --server http://127.0.0.1:8188 --plan
```

--plan은 파일 목록·순서·해시·워크플로우 구조를 기록한다. 서버 요청, 업로드, 모델 실행은 없다.
이미지 디코딩과 서버의 노드·모델 설정 검증은 실제 실행에서 수행한다.

```bash
python3 tools/run_project.py \
  --input /media/tosol/ng/manga/book01 \
  --project /media/tosol/ng/manga-results/book01 \
  --workflow /media/tosol/ng/workflows/book08.api.json \
  --server http://127.0.0.1:8188 --export
```

같은 명령을 다시 실행하면 재개한다. 완료된 원본 해시와 결과 파일을 확인해 재사용한다.
이미 실패한 페이지는 자동 반복하지 않는다. --retry-failed를 추가하면 실패한 페이지를 한 번씩 다시 시도한다.
--stop-on-error는 일반 페이지 오류에서도 중단하는 선택 사항이다. --non-recursive는 하위 폴더를 제외한다.
--page-timeout의 기본값은 페이지당 3,600초이며, 시간 초과 시 다음 장을 제출하지 않는다.
--max-pixels는 현재 08 식자 모듈의 16,777,216픽셀 한도 이내로만 지정할 수 있다.
서버 프록시 인증이 필요하면 COMFY_API_TOKEN에 접두사 없는 토큰을 설정한다. 별도 패키지는 추가하지 않는다.
종료 코드는 현재 페이지 전부 완료 0, 실행은 끝났지만 실패·검수 페이지 있음 3, 중단·구성/통신 문제 2,
Ctrl+C 130이다. 일부 페이지만 성공한 프로젝트를 자동화에서 전체 성공으로 판단하지 않게 구분한다.

## 결과와 재개 기준

project.json은 상대 파일명·자연순 순서·원본 SHA256·워크플로우 설정을 묶는다.
1, 2, 10 순서로 읽으며 하위 폴더의 같은 파일명과 내용이 같은 별도 페이지도 각각 보존한다.
페이지 폴더 ID는 전체 상대 경로의 해시다. 모델을 다시 실행하는 경우 attempt 번호가 증가하고
이전 결과는 남는다. 상태 파일은 임시 파일에 기록·fsync한 뒤 교체한다. 프로젝트별 OS 파일 잠금은
같은 프로젝트 실행기의 동시 실행을 막으며, 프로세스 종료 시 잠금이 해제된다.

| 위치 | 내용 |
| --- | --- |
| project.json | 입력 목록·순서·파일 해시·서버/워크플로우 설정·제거된 입력 이력 |
| workflow.api.json | 프로젝트에 사용한 설정 사본 |
| summary.json | 페이지별 상태·실패 노드·요약 오류·상태 파일·결과 경로 |
| pages/p…/attempt-000001/state.json | 작업 ID, UTC 시각, 업로드/서버 출력 대응, 파일 해시, 상세 오류 |
| 같은 attempt 폴더의 input.png | EXIF·색상 모드를 정리한 실제 업로드 입력 |
| 같은 attempt 폴더의 source.json / target.json | API 기록에서 확인된 원문·번역 검수 JSON |
| 같은 attempt 폴더의 result.png | 해당 작업의 최종 SaveImage 결과 |
| exports/판본해시/ | --export로 만든 000001.png 등의 읽기 순서 이미지와 index.json |

--export는 completed와 unchanged_blank만 복사한다. 실패·검수 페이지 번호는 빈 번호로 남고
index.json에 기록된다. 페이지 추가·변경으로 순서가 바뀌면 다른 판본 폴더를 사용해 과거 출력과
섞지 않는다. 원본은 수정하지 않는다. 수정된 프로젝트 결과 파일도 자동으로 덮어쓰지 않는다.

현재 설정은 프로젝트 안에서 고정한다. JSON 키 순서나 UI 제목 변화는 실행 설정 변경으로 보지 않지만,
모델·번역·식자 설정이 바뀌면 새 프로젝트 폴더를 사용한다. 서버 코드·가중치를 같은 이름으로 교체한
경우도 새 프로젝트로 구분한다. 서버의 모델 파일 내용까지 자동으로 지문을 수집하는 기능은 없다.

## 예외 처리

| 상황 | 처리 |
| --- | --- |
| 손상·읽기 불가·링크·256MiB 초과 입력 | 페이지 실패 기록, 다음 장 진행 |
| 읽을 수 없는 하위 폴더·링크 하위 폴더 | 누락된 페이지를 모르는 채 진행하지 않고 스캔 중단 |
| 다중 프레임 GIF/TIFF, 고비트 이미지 | 임의 첫 프레임 선택·포화 변환 없이 명시적 입력 오류 |
| EXIF 회전, 흑백/CMYK, 투명 PNG | 회전 반영, RGB 변환, 투명 배경은 흰색 합성 후 업로드 |
| 검출 경계 복구/OCR 품질/식자 맞춤 실패 | 해당 페이지 실패, 가능한 중간 JSON 보존, 다음 장 진행 |
| 단색 RGB 페이지에서 검출 0개 | 실제 출력 픽셀이 원본과 같을 때 unchanged_blank |
| 비단색 페이지의 검출 0개 또는 제외된 효과음 | 원본 출력 보존, needs_review. 글자 없음으로 확정하지 않음 |
| POST /prompt 응답 유실 | 제출 전 저장한 UUID/프로젝트 토큰으로 조회. 자동 재제출하지 않음 |
| 기존 작업이 있는데 새 파일이 앞 순서로 추가됨 | 기존 작업부터 먼저 조회·회수한 뒤 새 장 제출 |
| 대기 중인 원본이 변경·삭제됨 | 기존 업로드의 결과부터 회수. 새 버전은 별도 시도, 삭제 이력도 유지 |
| 작업이 큐와 이력에서 모두 사라짐 | 전체 추가 제출 중지. 결과를 모르는 작업을 복제하지 않음 |
| 시간 초과·통신 끊김 | 작업 ID 유지, 추가 제출 중지, 같은 프로젝트로 재개 |
| 결과 다운로드 실패·로컬 결과 누락 | 기존 작업에서 다시 회수. 모델을 다시 실행하지 않음 |
| 이미 존재하는 결과 파일이 수정됨 | 자동 덮어쓰기 없이 needs_review |
| GPU 메모리/CUDA 오류, 디스크 부족, 권한/모델/의존성 오류 | 전체 추가 제출 중지 후 서버 확인 |
| 최종 이미지 누락, 다른 시도의 파일, ID/좌표 불일치, 잘못된 JSON | 완료 판정 거부·추가 제출 중지 |
| Ctrl+C | 새 제출 중지. 서버 전체 /interrupt나 다른 사람의 큐 작업을 조작하지 않음 |

서버가 실제로 끝났다고 보고하고, 현재 시도에 속한 PNG와 두 검수 JSON의 크기·ID·원문·좌표가
맞아야 완료로 기록한다. completed는 실행 완료 상태이며 OCR·번역 의미의 정확도 인증이 아니다.
각 페이지를 처리한 뒤 상태 파일을 다시 읽어 최종 상태가 실제 기록됐는지도 확인한다.
통신이나 구성 문제를 무시하고 다음 장을 쌓아 두는 방식은 사용하지 않는다.

## 이번에 수정한 시뮬레이션의 맹점

기존 모의 GrowMask는 scipy iterations=0이 원본 유지가 아니라 수렴할 때까지 확대라는 점을
잘못 적용했다. 실제 노드의 0 확대와 맞게 그대로 복사하며 음수는 축소로 처리한다.
0·양수·음수에서 페이지 전체를 채우지 않는 검사를 추가했다.

원문·번역 저장 노드 뒤의 PreviewAny가 실행되기 전에 식자가 실패할 수도 있었다.
MangaSaveReview는 이제 저장 직후 text와 상대 파일명을 UI/API 기록에 남긴다. 기존 STRING 출력은
유지한다. 프로젝트 실행기는 이 직접 저장 결과를 우선 사용하고, 이전 서버의 PreviewAny도 지원한다.
기본 미리보기 연결은 유지한다. 실제 실패 경로에서도 저장 노드 UI는 남고 PreviewAny는 아직
실행되지 않은 상황을 검사한다.

## 재현 명령과 관측 결과

검증 환경은 PyTorch CPU다. RF-DETR/Hayai/vLLM/Qwen 호출은 명시적인 테스트 대역이다.
커스텀 노드, 실제 폰트 픽셀, 마스크, 타일 계획/합성, JSON 검증과 파일 저장은 실제 코드를 실행한다.

```bash
python3 tools/simulate_project.py --destination /tmp/manga-project-simulation-new
python3 -m pytest tests -q --confcutdir=tests
```

시뮬레이션은 증거가 남아 있는 폴더를 덮어쓰지 않는다. 다시 실행하려면 새 destination을 지정한다.

11장 혼합 폴더에서 정상 4장, 단색 빈 페이지 1장, 검출 0개 검수 1장, 의도적 실패 5장을 얻었다.
실패는 미복구 타일 경계, 반복 OCR, 원문이 남은 제거 결과, 식자 불가, 손상 파일을 각각 넣었다.
손상 파일은 모델에 제출되지 않았고, 실패 이후 정상 페이지도 저장됐다. 재개 시 추가 제출은 0건이다.
하위 폴더의 같은 파일명도 별도 결과가 됐다. 모서리·native/compact 임계 크기·좁고 긴 페이지,
중복·빈틈 없는 축 타일링은 별도 행렬 검사로 확인한다. HTTP 업로드 multipart·작업 제출·이력·이미지
회수도 로컬 HTTP 서버 대역과 실제 urllib 왕복으로 검사한다.

## 남은 품질·기능 범위

번호가 포함된 같은 사각형 안에서 번역을 배치하면 보존된 번호 칸으로 들어갈 수 있다.
합성 번호 표식으로 실제 CPU 폰트를 렌더링한 결과 표식 사각형 안의 번역 알파 540픽셀을 확인했다.
검출 박스와 새 번역 간 충돌 검사가 통과해도 이 경우는 자동 보호되지 않는다. 번호/본문의 배치 공간과
제목·소제목의 스타일 경계를 따로 추정하는 개선이 필요하다. 이를 해결했다고 기록하지 않는다.

이전에 수동 09가 필요했던 표지의 자동 검출은 미해결이다. 이번 실행기는 08의 실패를 기록하고 다음
장을 처리하며, 그 표지를 자동으로 읽게 만드는 새 검출 백엔드를 구현한 것은 아니다.
프로젝트 전체의 앞뒤 문맥·용어집 기반 번역 일관성, 페이지별 GUI 검수/부분 재실행, CBZ/PDF 직접
가져오기는 아직 지원하지 않는다. 입력은 폴더의 이미지 파일이다.

실제 ComfyUI 서버와 GB10 모델을 사용하는 폴더 전체 실행은 여기서 수행하지 않았다.
사용자가 공유한 단일 공략집의 저장 성공과 이번 CPU/API 대역 검증을 구분한다.

프로토콜은 [공식 ComfyUI 서버 라우트](https://docs.comfy.org/development/comfyui-server/comms_routes),
[공식 API 예제](https://github.com/Comfy-Org/ComfyUI/blob/master/script_examples/websockets_api_example.py),
[서버 구현](https://github.com/Comfy-Org/ComfyUI/blob/master/server.py),
[기본 PreviewAny](https://github.com/Comfy-Org/ComfyUI/blob/master/comfy_extras/nodes_preview_any.py)를
2026-10-17에 확인했다.
