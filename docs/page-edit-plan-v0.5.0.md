# v0.5.0 — 페이지 편집 계약과 통일 식자 방향

## 사용법

`git pull` 후 ComfyUI 재시작·브라우저 새로고침을 하고 새 통합 08의 일반 `.json`을 가져온다. 새 노드와 연결이 추가되어 이전 캔버스에 코드만 업데이트하면 새 편집 경로와 방향 선택이 연결되지 않는다. 번역 서버·모델·폰트 등 기존 사용자 설정은 다시 확인한다.

입력 옆 `번역문 방향 · 가로 / 세로 통일` 노드의 `lettering_direction`에서 선택한다. 방향 설정은 식자에만 연결하여, 방향만 바꿨을 때 검출·OCR·번역·제거의 ComfyUI 노드 캐시를 무효화하지 않는다.

| 설정 | 결과 |
|---|---|
| 가로 통일 — 새 08 기본 | 모든 번역 영역을 가로로 식자 |
| 세로 통일 · 오른쪽 열부터 | 모든 번역 영역을 세로로 식자하고 오른쪽 열부터 읽음 |
| 세로 통일 · 왼쪽 열부터 | 모든 번역 영역을 세로로 식자하고 왼쪽 열부터 읽음 |
| 원문 따라 자동 | 원문 픽셀의 방향 추정과 영역별 수동 방향을 사용 |

통일 모드는 `MangaLetterPlan.direction`, 영역별 `direction`, 준비 JSON의 `layout.direction`보다 우선한다. OCR의 `text_direction`은 원문을 읽는 설정이므로 바꾸지 않는다. 원본 보존 대상으로 남긴 글자나 효과음에는 새 식자를 하지 않는다. `line_breaks=reflow`일 때 통일 방향의 단일 줄바꿈을 재배치하고 빈 줄 문단을 유지한다. `preserve`와 `strict`의 명시적 줄바꿈은 유지한다.

폴더 전체에 같은 캔버스 설정이 적용된다. 이미 완료한 페이지에 새 방향을 적용하려면 새 `project_name`으로 실행한다. 기존 프로젝트는 처리 설정의 fingerprint가 다르면 재개를 거부하며, 기존 시도·결과를 덮어쓰지 않는다. 이 릴리스의 새 그래프도 이전 프로젝트와 설정이 다르므로 새 프로젝트 이름을 사용한다. 과거 결과는 기존 폴더에 남는다.

## 같은 편집 결정의 전달

이전 그래프의 제거 계획은 OCR 이전 크롭 명세를 받았다. v0.5.0은 다음 의존성을 명시한다.

1. 검출 → 크롭/행 정리 → OCR → 원문 저장 → 번역.
2. `MangaPageEditPlan`에서 교체/원본 보존을 결정하고 번역과 함께 저장.
3. 저장된 같은 명세와 필터링한 마스크로 제거 계획·식자를 실행.
4. 폴더 수집에서 명세와 최종 원본 보존 픽셀을 검증.

`page_edit.py`가 판단과 검증을 소유한다. 새로운 범용 그래프 실행기나 모델 서비스는 추가하지 않는다. ComfyUI의 현재 캔버스·일반 Run·기본 미리보기·중지 흐름을 계속 사용한다.

| 영역 | 기본 처분 | 편집 동작 |
|---|---|---|
| 원문·번역문·좌표를 검증한 영역 | replace | 제거 마스크에 허용하고 식자 |
| 픽셀로 확인된 점 나열이며 번역이 같은 점 나열 | preserve | 제거 전부터 원본 보존 |
| 사용자가 원본 보존을 지정한 영역 | preserve | 제거·새 식자 제외 |
| 검출 마스크의 획이 어떤 편집 영역에도 배정되지 않음 | preserve + needs_review | 미배정 획의 경계 상자 보존 |
| 보존 상자와 겹치는 교체 영역 | preserve + needs_review | 인접 영역을 부분 삭제하지 않고 전체 보존 |

초록/빨강 편집 미리보기는 각각 교체/원본 보존을 표시한다. `편집 보고서 → 미리보기 아무거나`에서 영역별 처분 이유와 미배정 획을 확인한다. 원문과 번역 저장에도 기존 미리보기를 유지한다.

`region_actions_json` 예: `{"r1":"preserve"}`. 허용 값은 `replace`와 `preserve`다. 존재하지 않는 ID나 다른 값은 오류다. 이 설정도 캔버스 설정이므로 폴더에서는 각 페이지의 같은 ID에 반복 적용된다. 한 페이지만 수동 검수할 때는 이미지 한 장 모드에서 사용한다. `replace`로 지정해도 미확정 경계의 보존과 겹치면 보호가 우선한다.

## 계약과 검증

- 명세는 schema, 원본 페이지 크기, `xyxy_pixels`, 원문·번역·좌표의 digest, 영역별 처분과 근거, 보호 상자를 기록한다. 식자 방향은 캔버스 설정과 식자 보고서에 기록한다.
- 계획 이후 원문·번역·좌표가 바뀌면 소비 단계에서 거부한다. 계획부터 다시 실행해야 한다.
- 검출 상자, 제거 허용 마스크, 실제 식자 프레임은 각각의 역할을 유지한다. 제거 허용은 교체 영역 내부로 제한하고 보호 상자를 제외한다.
- 단색 획 보완도 교체 영역에만 적용한다. 원본 보존 영역을 뒤에서 복원하는 것만으로 처리하지 않는다.
- 원본 보존은 식자 계획과 최종 알파 충돌 검사에도 전달한다. 폴더 수집은 최종 PNG의 보호 픽셀을 입력과 비교한다.
- 실제 식자 대상 수·면적의 공통 한도는 제거 전에 검사한다. 완전한 폰트·행 배치·말풍선 검사는 기존 식자 단계에서 수행한다.
- `completed`는 실행 완료다. 휴리스틱 OCR 통과나 기하 검사가 의미상 번역 정확성을 보증하지 않는다.

이전 준비 JSON의 `preserved_punctuation`은 식자 입력 경계에서만 읽는다. 새 경로는 일반 `source_preservation`으로 통합한다. 폴더의 원문·번역 산출물은 변함없이 모든 원래 영역 ID를 유지한다.

## 조사와 적용 범위

2026-10-18 KST 조사 시 다음 커밋의 원본을 읽고 설계의 책임 구분을 참고했다. 외부 구현을 복사하거나 의존성을 추가하지 않았다.

- [Koharu `85d6de3` 파이프라인](https://github.com/koharu-rs/koharu/blob/85d6de339ee7d486fe381249205126d944d40bb7/crates/koharu-pipeline/README.md): 페이지·단계별 입력/결과, 저장된 결과에 근거한 진행. [의미상 원문·번역 분리](https://github.com/koharu-rs/koharu/blob/85d6de339ee7d486fe381249205126d944d40bb7/crates/koharu-scene/src/components/text.rs).
- [BallonsTranslator `ea9dcd5` OCR 경계](https://github.com/dmMaze/BallonsTranslator/blob/ea9dcd5e18fb26091ec5c44ed947ce5e11b6c8d8/ballontranslator/modules/ocr/base.py): 실패한 단계가 이전 정상 텍스트를 손상하지 않는 처리.
- [manga-image-translator `d6de6ab` 실행 순서](https://github.com/zyddnys/manga-image-translator/blob/d6de6ab62a7be6afc0d07a3184149cdefbcd32f2/manga_translator/manga_translator.py): OCR·번역 후 필터링한 영역을 활용하는 마스크 정제.

이번 범위는 편집 계약과 방향 통일이다. 검출·OCR 모델이나 반복/누락 임계값은 바꾸지 않는다. 전체 파이프라인의 영속 단계 캐시, 실제 정답 페이지 기반 CER/누락률 평가, 식자 이전 전체 fit 사전계산은 완료한 기능이 아니다.

검증 결과와 실제 GPU 실행 여부는 [VALIDATION.md](../VALIDATION.md)에 구분해 기록한다.
