## 재현 및 변경

사용자가 제공한 1600×640 OCR JSON의 r3는 x=576px에서 끝나는 여러 행의
세로 조각, r5는 x=1024px에서 시작하는 반쪽 문단이었다. 검출 원시 응답과
실제 GPU 재실행은 확보하지 못했으므로 타일 경계가 유력한 원인이라는
판단과 아래 합성 재현의 확인 범위를 구분한다.

- 같은 크기와 경계의 합성 검출을 이전 코드에 넣으면 6개 논리 영역 대신
  세로 조각을 포함한 7개가 남았다. 본문 시작은 460px 대신 512px로 잘렸다.
- 내부 크롭 경계에 닿는 글자 검출에 원래 크롭과 잘린 방향을 기록한다.
- 전체/다른 타일의 온전한 같은 종류 검출이 마스크 픽셀의 98% 이상을 포함하면
  조각 사각형을 OCR에서 제외한다. 마스크가 없는 응답은 사각형 전체를 기준으로 한다.
- 부족하면 잘린 방향으로 문맥을 넓혀 최대 3단계 다시 검출한다.
  기본 상세 창 64개 + 추가 복구 16회 이내이며, 전체 페이지 1회를 포함한 최대 호출은 81회다.
  누적 검출 결과도 기존 512개 상한을 유지한다.
- 복구 실패·한도 초과는 OCR 전에 중단한다. 영역 정리 단계에도 미해결 조각 거부를 둔다.
- 조각 사각형은 OCR/식자에서 제외하고, segmentation 픽셀은 별도 `mask_fragments`로
  삭제 마스크에 합친다. 정상적인 세로 글자를 종횡비만으로 버리지 않는다.
- 노드 타입·입출력·08 그래프 연결은 유지한다. 기존 설정으로 업데이트 후 재시작하면 적용된다.

## 범위와 한계

RF-DETR·Hayai·번역 서버·Qwen 응답은 합성 테스트 대역이다. 사용자 이미지의 일본어
OCR 정확도나 실제 GPU 제거 품질이 개선됐다는 실측 결과는 아니다. 기본 이미지
노드도 CPU 등가 구현으로 실행했으며 실제 ComfyUI executor·프런트엔드 검증은 하지 않았다.
경계에 닿지 않는 검출 오류와 모든 검출에서 빠진 글자는 이 복구 규칙으로 보증하지 않는다.
98% 마스크 포함 판정은 모델 독립적인 기하 휴리스틱이며 의미상 문단 검증은 아니다.

설치 ZIP은 CRC와 모든 포함 파일의 SHA256, 압축 해제 후 플러그인 import를 검사한다.
이번 작업에는 호스트 torch/CUDA/vLLM 또는 Koharu 바이너리 변경이 없다.
