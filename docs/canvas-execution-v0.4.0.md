# v0.4.0: 폴더도 현재 캔버스에서 실행

폴더 시작 노드만 끝낸 뒤 서버 작업자가 별도 API 그래프를 제출하던 기본 동작을 교체했다. 한 번의 일반 ComfyUI 실행이 한 페이지의 입력 → 검출 → OCR → 번역 → 원문 제거 → 식자 → 저장을 수행한다. 노드 강조, 기본 미리보기, 실행 이력과 중지 대상은 실제 그 페이지의 prompt다.

브라우저 확장은 실제 페이지 완료 이력을 확인하고 결과를 기록한 뒤 `app.queuePrompt(0, 1)`로 현재 캔버스를 다음 페이지에 대해 실행한다. 서버의 프로젝트 전용 추론 스레드나 숨은 자식 prompt는 사용하지 않는다. 내부 HTTP 두 경로는 완료 기록 수집과 연속 실행 중지에만 사용한다. 기존 CLI 실행기는 호환 도구로 남아 있지만 통합 워크플로우의 폴더 실행에서는 호출하지 않는다.

## 업데이트와 실행

1. 저장소를 업데이트하고 ComfyUI를 재시작한다. 브라우저도 새로고침한다.
2. 새 **08-integrated-tiled-cleanup-lettering.json**을 가져온다. 예제는 여전히 이 통합 워크플로우 하나다. 기존 그래프는 폴더별 저장 경로 연결 세 개가 없으므로 새 그래프가 필요하다.
3. 기존 모델·번역 URL·폰트 설정을 옮기고 첫 노드에서 `폴더 프로젝트`, `input_folder`, `project_name`을 설정한다. PC 폴더 업로드 버튼도 같은 노드에 있다.
4. `시작·재개`로 Run한다. **첫 Run부터 실제 첫 페이지를 처리**한다. 브라우저를 열어 두면 완료 후 다음 페이지가 일반 실행 큐에 들어간다.

첫 노드의 `현재 페이지 · 실시간 진행`에서 페이지 번호·파일명·현재 노드·제공되는 진행 수치를 확인한다. 연결된 `미리보기 아무거나`에는 프로젝트 집계가 갱신된다. 각 이미지/JSON 미리보기는 같은 페이지의 실제 중간 결과다. 별도 사이드바가 필요 없다.

## 중지·재개와 오류

| 동작 | 결과 |
|---|---|
| 기본 ComfyUI 중지 | 현재 네이티브 실행을 중단하고 후속 제출도 멈춘다. |
| 입력 노드의 `연속 처리 중지 · 현재 페이지 이후` | 현재 페이지는 마무리하고 다음 페이지를 제출하지 않는다. 다른 작업을 취소하지 않는다. |
| `상태 확인` + Run | 큐/이력과 저장 기록을 대조한다. 다음 페이지를 제출하지 않는다. |
| `시작·재개` + Run | 완료 페이지를 재실행하지 않고 남은 페이지부터 실행한다. |
| `실패 재시도` + Run | 실패 페이지와 남은 페이지를 선택한다. 한 연속 실행에서 같은 실패 페이지를 반복 재시도하지 않는다. |

알려진 OCR·경계·식자 품질 실패는 해당 페이지에 진단을 남기고 다음 페이지를 처리한다. 메모리·디스크·서비스·설정 오류, 사용자 중지, 오류 상세 유실과 구현 오류는 연속 실행을 멈춘다. 페이지의 실패 노드·예외·원래 prompt ID와 시도 기록은 보존한다.

브라우저를 닫거나 연결이 끊기면 다음 페이지 자동 제출은 중단된다. 이미 접수된 현재 페이지는 ComfyUI에서 계속 실행될 수 있다. 다시 열어 같은 노드에서 상태 확인/재개하면 그 prompt의 실제 이력을 먼저 수집한다. 브라우저를 닫은 채 전체 책을 계속 처리하는 방식은 이 캔버스 모드의 동작이 아니다.

서버 재시작 전에 `running`으로 남고 큐·이력에서 사라진 시도는 자동 실패로 꾸미지 않는다. [v0.3.20 복구 조건](restart-recovery-v0.3.20.md)에 따라 프로세스 시각으로 재시작이 증명되는 경우에만 명시적 `실패 재시도`에서 이전 시도를 보존하고 새 시도를 허용한다. 컨테이너 PID와 `/proc`의 PID가 다른 환경도 현재 프로세스의 실제 시작 시각을 조회한다.

## 기록과 호환

기존 `workflow_projects/<project_name>/`의 프로젝트·페이지·시도 기록을 재사용한다. 처리 설정이 같아야 하며 모델/번역/식자 설정을 바꾸면 새 프로젝트 이름을 사용한다. `canvas_run.json`은 현재 캔버스 연속 실행의 페이지 선택·진행·중지 정보를 보존한다. 기존 기록을 삭제해 재시작할 필요가 없다.

실시간 상태 위젯과 중지 버튼은 모델 입력이나 저장 위젯 값으로 직렬화하지 않는다. 자동 연속 실행 표식은 해당 일반 Run의 워크플로우 메타데이터에만 잠시 넣고 제거한다. 프로젝트/폴더/입력 모드가 바뀌거나 다른 그래프를 열면 이전 실행이 새 캔버스를 자동 실행하지 않는다.

CPU·브라우저 검증은 실제 프로젝트 기록과 프런트엔드 이벤트/큐 계약을 사용하되 모델 추론은 대역을 사용한다. 실제 DGX RF-DETR/Hayai/Qwen 품질은 별도 확인 대상이다.
