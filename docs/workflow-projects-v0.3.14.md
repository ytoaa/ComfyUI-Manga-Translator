# 같은 08 워크플로우에서 이미지와 폴더 처리

> 이 문서는 당시 버전의 기록이다. 현재 캔버스 실행과 실시간 상태 사용법은 [v0.4.0](canvas-execution-v0.4.0.md)을 따른다.

ComfyUI 캔버스의 **08 통합 워크플로우**를 사용한다. 첫 번째 ‘워크플로우 입력 · 이미지 / 폴더 프로젝트’ 노드에서 입력 방식을 고르고, 기본 **Run** 버튼으로 실행한다. 프로젝트 보고서도 캔버스에 연결된 기본 ‘미리보기 아무거나’에 표시한다.

업데이트 후 ComfyUI를 재시작하고 **새 08 JSON을 다시 불러온다.** 이전 08에는 새 입력 노드와 보고서 연결이 없다.

## 한 장 실행

1. `input_mode=이미지 한 장`으로 둔다.
2. 첫 노드의 이미지 선택/업로드 버튼으로 원본을 고른다.
3. 기존처럼 모델·번역·제거·식자 설정을 맞추고 Run을 누른다.

파일 읽기와 마스크는 ComfyUI 기본 `LoadImage` 구현을 사용한다. 기존 단일 페이지 처리 경로는 그대로 유지한다.

## 폴더 프로젝트 실행

예를 들어 ComfyUI 서버의 `input/manga_book/volume1/`에 원본 이미지들을 모은다. 하위 폴더도 포함한다. 파일을 한 이미지 배치로 합치지 않는다.

| 입력 노드 옵션 | 예시 | 의미 |
| --- | --- | --- |
| `input_mode` | `폴더 프로젝트` | 현재 08을 페이지별로 순차 실행 |
| `image` | 폴더 모드에서 무시 | 한 장 모드의 선택 이미지 |
| `input_folder` | `manga_book/volume1` | 서버 `ComfyUI/input/` 기준 원본 하위 폴더 |
| `project_name` | `volume1_ko` | 결과·설정·재개 기록을 구분하는 이름 |
| `action` | `시작·재개` | 새 프로젝트를 시작하거나 저장된 프로젝트를 재개 |

번역 서버·언어·모델·OCR·식자 옵션을 현재 캔버스에서 맞추고 **Run을 한 번** 누른다. 첫 실행은 현재 그래프와 설정을 저장한다. 이후 페이지마다 같은 그래프를 ComfyUI의 기본 큐에서 독립 실행한다. OCR 영역 목록이나 제거 타일이 다른 페이지와 섞이지 않는다. 다른 ComfyUI 작업은 기존 큐 규칙을 따른다.

입력 노드의 `project_report` 출력에 연결된 **프로젝트 진행·실패·결과 위치 · 미리보기 아무거나**에서 페이지별 상태와 저장 위치를 확인한다. OCR/번역 저장 결과에 연결된 기존 두 ‘미리보기 아무거나’도 유지한다. 처리 중에는 페이지 실행 정보 또는 프로젝트 보고서가 갱신된다.

## 일시정지·재개·실패 재시도

같은 입력 노드에서 `project_name`을 유지하고 `action`을 바꾼 다음 Run을 누른다.

| action | 동작 |
| --- | --- |
| `상태 확인` | 기록된 진행·실패·결과 위치를 보고서에 표시 |
| `일시정지` | 현재 페이지를 마친 뒤 다음 페이지 제출을 중단 |
| `시작·재개` | 기존 작업 ID와 결과 파일을 확인하고 완료 페이지는 건너뜀 |
| `실패 재시도` | 실패 페이지에 새 시도를 하나씩 추가하고 완료 페이지는 건너뜀 |

ComfyUI의 기본 중지 버튼으로 현재 페이지가 취소되어 오류 이력에 남으면 프로젝트도 추가 제출을 멈춘다. 중단된 페이지는 실패로 남기므로 다시 처리하려면 `실패 재시도`를 사용한다. 폴더 시작용 작업이 중지된 경우에도 페이지를 시작하지 않는다.

재개는 **처음 저장한 그래프와 설정**을 사용한다. 캔버스에서 모델·언어·식자 설정을 바꿔 새 결과를 원하면 새 `project_name`을 사용한다. 브라우저를 닫아도 서버에서 진행한다. 서버 재시작 후에는 같은 프로젝트로 재개한다. 큐/히스토리에도 작업이 없어 접수 여부를 확인할 수 없으면 자동으로 다시 제출하지 않고 멈춘다.

## 예외와 저장

- 일반 페이지의 OCR·검출 경계·식자 오류, 손상 이미지: 해당 페이지를 실패로 기록하고 다음 페이지 진행.
- 메모리·디스크·모델 구성 오류, 취소, 접수 여부 불명: 추가 제출을 멈추고 일시정지.
- 선택 검출이 없는 비단색 페이지: 원본을 보존하고 검토 필요. ‘글자가 없다’고 확정하지 않는다.
- 균일한 빈 이미지이고 선택 검출도 없으며 결과 픽셀이 같음: 빈 페이지로 기록.
- 기존 결과가 수정됐거나 누락됨: 기록을 확인해 기존 작업에서 복구하거나 검토 상태로 보존.

내부 작업 이미지의 재입력을 막기 위해 `input` 전체와 내부 `manga_translator` 작업 폴더는 선택할 수 없다. 외부 심볼릭 링크·다중 프레임·16비트 입력은 명시적인 정리가 필요하다. 현재 08의 페이지당 최대 크기는 16,777,216픽셀이다. EXIF 방향을 적용하고 투명 배경은 흰색에 합성하며 원본은 수정하지 않는다.

기록은 `ComfyUI/output/manga_translator/workflow_projects/<project_name>/`에 있다. 페이지마다 원본 정규화 PNG·결과 PNG·원문/번역 JSON·시도별 작업 ID를 보존한다. 프로젝트가 끝나면 완료한 페이지의 정렬된 복사본을 `exports/<판 ID>/000001.png` 형식으로 만든다. 실패·검토 페이지의 번호는 비워 두고 `index.json`에 남긴다. 실제 저장 위치와 상태는 보고서에 표시한다.

## 검증 범위

ComfyUI 프런트엔드 1.53.10에서 실제 08의 입력 위젯·기본 Run·기본 ‘미리보기 아무거나’를 검사한다. 기본 큐와 prompt 처리 함수의 상류 코드를 사용한 검증에서도 모델/실행 스케줄러는 CPU 대역이다. DGX의 실제 RF-DETR/Hayai/번역/Qwen GPU 추론과 구분한다.

일부 표지 자동 검출, 숫자 칸/제목의 의미 구분, OCR 의미 정확도, 페이지 간 용어 공유는 별도 개선 대상이다. 완료는 실행과 결과 파일 검사가 끝났다는 뜻이다.
