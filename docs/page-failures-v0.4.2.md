# v0.4.2: 경계 복구·혼합 문자 폰트·중첩 말풍선

실제 18페이지 프로젝트는 completed=6, needs_review=2, unchanged_blank=2, failed=8로 끝났다. 실패 노드는 검출 경계 복구 5페이지(04/08/09/11/14), 폰트 문자 누락 2페이지(06/17), 말풍선 중첩 1페이지(12)였다. 큐 복구를 거쳐 첫 페이지의 4번째 시도가 완료된 것과 별개로, 페이지 처리 품질 경로를 보완한다.

## 경계 재검출

큰 페이지의 1152px 타일 경계에서 나온 작은 조각을 한 방향으로 수천 픽셀 늘린 복구창만으로 재검출하면 원래 검출 문맥과 크게 달라질 수 있다. 양축에 native 크기 공간이 있는 페이지에서는 조각 중심의 1152px 정사각 문맥, 잘린 방향으로 옮긴 문맥을 먼저 시도한다. 여러 조각에 균등하게 기회를 준 뒤 기존 확장·작은 문맥 전략을 사용한다.

원래 .98 지지 영역 coverage 기준, 같은 라벨 확인, 조각 연결의 양끝 관측, 전체 16회 복구 예산은 유지한다. 0%나 83.1% coverage를 성공으로 바꾸거나 조각을 삭제하지 않는다. 미복구 시 `ComfyUI/output/manga_translator/detection_failures/`에 전체 재검출 JSON과 최대 native 크기의 주변 PNG를 저장하고 페이지 실패를 유지한다. 원본 전체는 폴더 프로젝트의 시도별 input.png에 있다.

보고된 다섯 좌표를 사용한 대역 검출 시뮬레이션은 정사각 문맥에서 잘림 없는 검출을 반환할 때 원래 페이지 좌표와 지지를 보존하는지 확인한다. 이 원본 5페이지의 실제 RF-DETR 재실행 결과를 뜻하지 않는다. 검출기가 새 문맥에서도 글자를 찾지 못하면 실패 진단이 필요하다.

## 일본어가 섞인 번역문과 폰트

동봉 나눔고딕은 `ー`, `グルン`을 지원하지 않아 식자 계획이 중단됐다. 통합 식자 계획은 선택 폰트를 먼저 검사하고, 글자가 빠졌을 때만 번역문 전체를 지원하는 실제 폰트로 해당 영역을 대체한다. 한글만 있는 영역과 지원되는 선택 폰트는 유지한다. 폰트가 전혀 없거나 어떤 후보도 모든 문자를 지원하지 않으면 계속 명시적으로 중단한다.

동봉 `MangaSansKR-Fallback.ttf`는 OFL의 Noto Sans KR에서 만든 wght=400 정적 폰트다. 원문 Unicode를 지우거나 장음 기호를 하이픈으로 바꾸지 않는다. 계획과 렌더 보고서의 `font_fallback`에 요청 폰트·실제 폰트·사유를 기록하며, 대체 폰트의 실제 측정값으로 크기와 줄바꿈을 다시 맞춘다. 폰트 보완은 번역 언어·문장의 정확성을 보증하지 않는다. 일본어가 그대로 남아야 하는 내용인지도 검수한다.

원본 blob·SHA256, 파생 SHA256, OFL과 재현 도구는 `lettering/fonts/sources.json`, `NotoSansKR-OFL.txt`, `tools/build_fallback_font.py`에 있다. 실행 중 폰트 다운로드나 설치는 없다. `git pull`로 동봉 폰트를 받는다.

## 겹치는 말풍선

여러 말풍선 마스크가 같은 원문 잉크의 95% 이상을 각각 포함할 때, 모양이 다르면 종전에는 즉시 중단했다. 이제 공통 마스크의 한 연결 성분이 여전히 원문 잉크의 95% 이상을 포함하는지 확인한다. 그 공통 내부에 여유를 두고 번역문의 모든 alpha 픽셀을 제한한다. 특정 말풍선을 임의 선택하거나 마스크를 합쳐 공간을 늘리지 않는다.

공통 내부가 잉크를 충분히 포함하지 않거나, 최소 가독 크기에서 번역문이 들어가지 않으면 실패한다. 성공 보고서에는 `overlap_resolution.strategy=common_mask_intersection`과 관련 마스크 ID를 기록한다.

## 기존 프로젝트에 적용

코드 업데이트 후 ComfyUI를 재시작하고 브라우저를 새로고침한다. 통합 08의 연결·위젯·기본값과 프로젝트 설정 fingerprint는 바꾸지 않았다. 기존 프로젝트 이름과 워크플로우를 유지한 채 `실패 재시도`를 실행하면 실패 8페이지에 새 시도를 만든다. 이미 완료되었거나 needs_review/unchanged_blank인 10페이지는 이 동작에서 재실행하지 않는다.

02_2.jpg는 선택 글자 검출 0개여서 실제 무문자 페이지인지 검수해야 한다. 18_18.png는 효과음 제외 상태에서 효과음 검출이 있었기 때문에 원본 유지·검수로 분류됐다. 이 두 상태를 실패 또는 번역 완료로 임의 변경하지 않는다. 03/16의 uniform_rgb_pixels는 정규화한 입력이 균일색이었다는 기록이다.
