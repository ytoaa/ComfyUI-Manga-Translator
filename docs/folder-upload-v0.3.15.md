# v0.3.15 · 08 워크플로우 PC 폴더 업로드

v0.3.14에서 폴더 프로젝트 실행을 08의 첫 `MangaWorkflowInput` 노드로 옮기면서, 기존 v0.3.13 사이드바가 제공하던 브라우저 폴더 업로드도 함께 제거됐다. 따라서 `input_folder`에는 이미 ComfyUI 서버의 `input/` 아래에 존재하는 폴더만 직접 입력할 수 있었고, PC 폴더를 선택하는 동작은 제공되지 않았다.

v0.3.15는 사이드바나 별도 프로젝트 HTTP API를 되살리지 않고 첫 입력 노드에 **`PC 폴더 업로드`** 버튼만 추가한다.

## 사용

1. 저장소를 업데이트한 뒤 ComfyUI를 재시작한다.
2. 브라우저도 새로고침한다. 오래 열린 탭이면 강력 새로고침을 권장한다.
3. 08의 첫 `워크플로우 입력 · 이미지 / 폴더 프로젝트` 노드에서 `PC 폴더 업로드`를 누른다.
4. 브라우저 폴더 선택기에서 원본 이미지 폴더를 고른다.
5. 지원되는 이미지가 ComfyUI 기본 `/upload/image` 경로를 통해 순차 업로드된다. 하위 폴더 구조도 유지한다.
6. 모든 파일 업로드가 성공하면 노드가 자동으로 `input_mode=폴더 프로젝트`로 바뀌고 `input_folder`에 `manga_uploads/<고유ID>/<원본폴더명>`이 들어간다.
7. 프로젝트 이름이 비어 있거나 기본값 `book_01`이면 선택한 폴더 이름을 기본 프로젝트 이름으로 넣는다.
8. 기존처럼 `시작·재개` 상태에서 Run을 누른다.

서버에 이미 원본 폴더가 있다면 업로드 버튼을 사용할 필요가 없다. 기존처럼 `input_folder`에 ComfyUI `input/` 기준 상대 경로를 직접 입력하면 된다.

## 구현 경계

폴더 선택에는 브라우저의 `webkitdirectory`를 사용한다. 실제 파일 저장에는 ComfyUI의 기본 이미지 업로드 경로 `/upload/image`와 `type=input`, `subfolder`를 사용한다. 별도 업로드 서버 라우트와 사이드바를 추가하지 않는다.

프런트 보조 버튼은 실제 워크플로 입력이 아니므로 노드 위젯의 마지막에 추가하며 workflow 저장과 prompt/API 직렬화 양쪽에서 제외한다. 기존 08의 입력 위젯 순서와 저장된 값에 영향을 주지 않아야 한다.

각 업로드는 고유한 `manga_uploads/<id>/...` 아래에 저장하고 `overwrite=false`로 전송한다. 중간 업로드가 실패하면 `input_folder`를 새 경로로 전환하지 않으므로 부분 업로드가 자동으로 프로젝트 실행에 들어가지 않는다. 실패한 임시 업로드 폴더는 필요하면 서버에서 정리할 수 있다.

## 지원 형식과 한계

현재 프로젝트 입력과 같은 PNG, JPG/JPEG, WebP, BMP, TIFF, GIF 파일을 대상으로 한다. 폴더 안의 다른 파일은 무시한다. 대용량 파일의 실제 허용 크기는 ComfyUI 서버의 업로드 제한을 따른다.

폴더 업로드가 끝났다는 것은 전송 성공을 뜻하며 이미지 디코딩, RF-DETR/Hayai/Qwen 품질을 보증하지 않는다. 프로젝트 실행 시 손상 이미지나 처리 오류는 기존 페이지별 실패/재개 정책을 따른다.
