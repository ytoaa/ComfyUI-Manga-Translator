# CPU 대체 모델 적용 검사 · v0.7.8

번역을 제외한 검출·OCR·배경 복원·식자 경로의 대체 가능성을 평가합니다. 기존 RF-DETR/Hayai 기본값은 유지하고 모델 선택 노드를 추가했습니다. 가중치·입력 이미지·마스크·검출/OCR 응답·생성 결과는 Git과 실행 ZIP에 포함하지 않습니다.

## 추가한 경로

| 영역 | 적용 | 범위와 제한 |
|---|---|---|
| 검출 | CTD ONNX · raw blocks | OpenCV DNN 실행, YOLO block+NMS와 UNet 획 지지. upstream의 문단 그룹화/마스크 정제 구현을 복사하지 않은 별도 어댑터 |
| 검출 | PP-OCRv6 + CTD ink | 공식 medium DB 검출 PyTorch 가중치 + CTD 획. DB 영역을 직사각형 글자 마스크로 취급하지 않음 |
| OCR | PP-OCRv6 · multilingual (CPU) | medium recognition Safetensors. 48px BGR, 긴 세로 크롭 회전, greedy CTC. 한국어 인식 보장 아님 |
| OCR | Manga OCR · Japanese | 기존 선택형 엔진을 같은 입력에서 재평가. 새 모델로 가장하지 않음 |
| 제거 | LaMa / Anime LaMa | 실제 TorchScript 모델로 남은 타일을 생성하고 기존 보호/마스크 합성 계약 적용 |

검출 대안 두 종류에는 **말풍선·컷·효과음 분류가 없습니다.** 효과음처럼 보이는 문자도 text로 반환하므로 `include_sfx=False`만으로 효과음을 제외할 수 없습니다. 말풍선 경계 인증 대신 기존 원문 프레임 fallback을 사용하게 되는 범위가 있습니다. 획 지지가 없는 후보는 보존·검수하며, 그 보호 박스와 다른 후보가 겹치면 기존 안전 검사가 중단할 수 있습니다. 보존/중단은 처리 완료가 아닙니다.

전처리·핀된 revision·SHA256은 `adapters/alternative_files.py`에 있습니다. CTD의 GPL 응용프로그램 코드를 벤더링하지 않습니다. 모델 출처·조건은 [제삼자 고지](../../THIRD_PARTY_NOTICES.md)를 따릅니다. ONNX Runtime 경로는 원격 진단 통신에 대한 자동 검토 거부 후 제외했으며 최종 CPU 검사에서 사용하지 않습니다. OpenCV와 PyTorch만으로 실제 추론합니다.

## ComfyUI에서 선택

기존 ComfyUI Python 환경에 선택형 의존성을 설치하고 재시작합니다. 현재 torch는 그대로 사용합니다.

```bash
python -m pip install -r requirements-alternatives.txt
```

- OCR: 기존 **OCR 엔진 · 모델 자동 준비**의 engine에서 PP-OCRv6 또는 Manga OCR을 선택하고 기존 adaptive OCR의 model 입력에 연결합니다. PP의 auto는 CPU이며 cuda 명시는 거부합니다. Hayai 기본 선택은 유지합니다.
- 검출: **대체 검출 모델 · CPU**의 모델 출력을 기존 상세 검출의 model에 연결합니다. CTD .4 / PP .45를 이번 검사에서 사용했습니다. 기존 RF용 임계값이 새 모델의 같은 정확도를 뜻하지 않습니다.
- 제거: 기존 **MangaInpaintPlan**의 plan을 **대체 타일 제거 · 보호 영역 유지**의 plan에, **대체 제거 모델 · LaMa / Anime LaMa** 출력을 model에 연결합니다. cleaned_page / cleanup_report를 기존 지운 배경 checkpoint와 식자 경로에 연결합니다. Qwen 타일 생성/assembly 부분을 이 노드로 대신합니다. 번역·편집 문서·원문/제거 마스크는 기존 연결을 유지합니다.

빈 제거 계획은 lazy 모델 입력과 실제 추론을 생략합니다. 단색 제거가 끝난 페이지도 불필요하게 생성하지 않습니다. 실제 타일은 기존 512 core+128 문맥 계획을 사용합니다. 제거 마스크 바깥과 보호 영역은 원본 픽셀을 유지합니다. strict_cleanup은 원문 변화 휴리스틱이며, 글자 잔존이나 그림 복원의 의미적 정확성을 인증하지 않습니다. `blend_width=8`은 마스크 안쪽의 합성 범위이며 넓은 마스크 안의 그림 손상까지 막지는 못합니다.

선택형 모델은 `ComfyUI/models/manga_translator/alternatives/{ctd,pp-det,pp-rec,lama,anime-lama}`에 설치됩니다. 누락 시 고정 URL만 내려받고 SHA256을 확인한 후 원자적으로 설치합니다. 수정된 폴더는 덮어쓰지 않습니다. PP 검출은 CTD도 필요합니다. 추론 전후 모델 세대를 확인하고 checkpoint에 의존 모델 핀을 포함합니다. CPU 스레드 수는 ComfyUI/실행 환경 설정을 따르며 노드에서 전역 스레드 설정을 바꾸지 않습니다.

## 실제 비교 범위

앞선 [만화·반투명 검사](manga-transparency.md)의 **동일 입력 바이트**를 사용합니다. 생성 배경 2개 × 16조건의 32페이지와 손그림 만화 1페이지, 알려진 OCR 40크롭(서로 다른 PNG 34개)과 수동 전사 6크롭입니다. 새 사용자 원본 9장의 재실행으로 표현하지 않습니다. 9장 전부 해결되었다는 근거도 아닙니다.

추론은 CPU와 고정 가중치로 실행합니다. HF offline 및 Python 네트워크 연결 차단을 사용하며 clean 정답은 채점에만 씁니다. 제거 검사에는 정확한 생성 기하를 명시적으로 공급하므로 탐지까지 해결한 결과가 아닙니다. 다른 모델을 reference 이미지로 대체하지 않습니다.

실제 연결 검사는 blank/opaque/alpha128/borderless/outlined-sfx/vertical-ruby × 배경 2개 × 조합 3개의 **36조건**입니다. 조합은 이전 실제 RF 예측+Manga OCR+Anime LaMa, 새 CTD 실제 예측+Manga OCR+Anime LaMa, 새 PP 실제 예측+PP OCR+Anime LaMa입니다. 예측을 다시 읽되 OCR·문서 수집·편집 계획·LaMa·식자·합성은 실제 코드를 실행합니다. 번역 API는 호출하지 않고 같은 고정 한글 시험문장을 사용합니다. RF를 새로 추론한 것으로 세지 않습니다.

모델 수치와 완성/보존/거부는 비공개 비교 묶음의 원시 JSON으로 제공합니다. 검출 국소화 기준, OCR 완전 일치, 공백 제외 내용 일치, 글자 위치의 복원 오차, 그림 손상, 단계 종료를 구분합니다. 복원은 확률적 모델의 추론 완료와 독립 정답 품질을 따로 평가합니다.

## 실제 측정 결과

같은 환경의 기존 Hayai를 다시 실행해 선택형 의존성 설치 후에도 실제 인식이 동작함을 확인했습니다. Python3.12 / torch2.6.0+cpu / torchvision0.21.0+cpu / transformers5.13.0 / OpenCV4.14.0, 프로세스당 CPU 2스레드입니다.

| 실제 OCR, adaptive 기본 설정 | 알려진 40크롭 정확 / 내용 일치 | 손그림 6크롭 정확 / 내용 일치 |
|---|---:|---:|
| 기존 Hayai v2, 재실행 | 14 / 19 | 5 / 5 |
| 기존 Manga OCR, 재실행 | 25 / 32 | 3 / 3 |
| 새 PP-OCRv6 medium | 20 / 20 | 3 / 3 |

공백·줄바꿈 차이만 내용 지표에서 제외합니다. 분할 없는 whole-crop 비교는 Manga 40개에서 정확14/내용32, 손그림 정확4/6; PP는 정확13/내용13, 손그림 정확4/6입니다. 각각 adaptive와 whole-crop 합계 92조건을 실제 실행했습니다. Hayai 재실행 46조건과 합쳐 OCR 230조건입니다. 이전 작은 패치 Hayai의 내용34/40은 앞선 별도 실험으로, 이번 환경에서 그 옵션까지 재실행한 수치가 아닙니다.

LaMa와 Anime LaMa는 각각 **32페이지 실행 오류 0**입니다. 각각 22페이지에서 실제 모델 26타일을 생성했고 나머지 10페이지는 단색/무문자 경로였습니다. 제거 마스크 바깥 픽셀과 보호 박스의 원본 유지 검사는 각각 32/32입니다. 이는 그림 전체 보존이나 완전 제거 성공률이 아닙니다.

모델이 실행된 22페이지에서 정답 글자 위치의 평균 절대 오차 감소율 중앙값은 LaMa **66.98%**, Anime LaMa **68.85%**입니다. 반면 확대된 제거 마스크 안에서 정답 글자 획 밖에 새로 생긴 그림 오차(기존 대비 최대 채널 오차 증가 >0.035)는 각각 **93,773 / 92,905픽셀**입니다. 페이지별/조건별 실패를 포함하므로 이 중앙값으로 배경 복원 완료를 선언하지 않습니다. 전후 이미지에서 글자 잔존과 무늬 흐림도 확인했습니다.

전체 CPU 회귀는 **794 PASS**, 그중 새 선택형 계약 검사는 **12개**입니다. UI/캔버스 JS 계약도 통과했습니다. 모델 대역을 사용하는 회귀 결과와 위 실제 가중치 추론의 품질 수치는 구분합니다.

검출은 CTD **19/32**, PP **18/32**가 같은 국소화 기준을 충족했습니다. PP의 1페이지는 원문과 보호 경계가 겹쳐 안전 중단했습니다. 이전 RF의 같은 입력 평가 24/32보다 높지 않습니다. 손그림 6문자군 페이지에서 CTD는 3크롭, PP는 4크롭을 수집했지만 큰 `ドン` 등 효과음 누락은 남았습니다. 크롭 수를 정답 문자군 인식 수로 세지 않습니다.

| 실제 연결 조합 | 마지막 합성 단계 종료 / 12 | 엄격 완성 | 그중 텍스트 페이지 / 무문자 대조 | 안전 중단 |
|---|---:|---:|---:|---:|
| 이전 실제 RF + Manga OCR + Anime LaMa | 12 | 4 | 2 / 2 | 0 |
| 실제 CTD + Manga OCR + Anime LaMa | 8 | 3 | 2 / 1 | 4 |
| 실제 PP 검출 + PP OCR + Anime LaMa | 10 | 2 | 0 / 2 | 2 |

엄격 완성은 전체 필요한 원문 내용 일치·오검출 편집 없음·그림 새 손상 없음·글자 위치 평균 오차 ≤0.035·검수 상태 없음·문자열 보존·보호 및 알파 밖 픽셀 보존을 함께 검사합니다. 각각 10개 텍스트 페이지 중 2/2/0개만 충족했습니다. 단계 종료 30조건의 양의 글자 알파 충돌은 0이며 보호·알파 밖 픽셀과 시험 문자열 유지 계약은 모두 충족했습니다. 이는 OCR 누락이나 제거 잔존을 해결했다는 뜻이 아닙니다. 6조건은 작은 원문 크기 제한으로 식자 계획에서 멈췄습니다. CTD의 일부 작은 원문은 실제 글자가 아닌 배경 오검출이었습니다.

## 남은 제한

대체 모델만으로 배경과 섞인 효과음·작은 대사 누락, 원문 중복, 반투명 말풍선 소유권을 모두 해결하지 못합니다. 후리가나의 9px source cap과 최소 10px 정책 충돌은 검출/OCR 가중치 교체와 다른 문제입니다. 최소 글자 크기를 조용히 낮추거나 원문을 자동 삭제하지 않습니다. 작은 문자로 중단한 페이지는 완료로 세지 않습니다.

PP OCR은 한 줄 인식 전처리와 세로 회전의 한계가 있고 Manga OCR도 분할/재시도에서 환각하거나 손그림에 퇴행할 수 있습니다. 모델별 페이지 전체 자동 선택은 도입하지 않습니다. LaMa는 Qwen이 없던 대기 영역을 실제 실행할 수 있게 하지만, 제거 마스크 안의 배경 무늬가 흐려질 수 있어 결과 검수가 필요합니다.

실제 ComfyUI executor, 사용자 DGX/GPU, 실제 번역 서버, 기존 Qwen과의 같은 입력 복원 품질 비교는 미검증입니다. 선택형 의존성은 같은 환경의 실제 Hayai와 Manga OCR로 호환성을 점검하지만 사용자의 모든 플러그인 의존성 조합까지 보증하지 않습니다.
