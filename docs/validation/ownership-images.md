# 원문 소유권과 독립 이미지 비교 · v0.7.17

실제 첨부 보고서에는 보호된 영역과 인접 크롭의 부분 원문 중복이 남았다. 보고서의 `issue=null`이나 픽셀 변경률은 번역 정확도를 증명하지 않는다. 이번 변경은 원시 말풍선/원문 마스크가 뒷받침하는 자동 복구와 식자 측정·배치 결함을 수정한다. 사용자 원본 2150×3035 이미지와 해당 실행의 RLE 마스크는 현재 자료에 없으므로, 실제 페이지의 r12–r14/r18/r21 해결을 확정하지 않는다.

## 발견한 경로와 수정

1. **검출 마스크와 OCR 이미지가 다른 범위를 사용했다.** 마스크끼리 겹치지 않아도 직사각 크롭은 옆 말풍선의 글자를 포함했다. 새로운 `source_partition.py`는 온전한 연결 성분 전부가 실제 말풍선 내부에 속하는 관측만 분리한다. 같은 소유자에 대한 부분 관측은 양성 획의 합집합으로 정리한다. 서로 다른 소유자의 원문은 합치지 않으며 미확인 관측이 중간 다리가 되어 두 소유자를 다시 합치는 것도 금지한다.
2. **같은 원문을 읽은 두 결과를 번역 단계가 각각 완성했다.** OCR 복사본의 소유 범위 밖을 중립 배경으로 바꾸고 동일 범위를 스타일 분석에 전달한다. 원본 페이지는 수정하지 않는다. 번역문/원문 문자열 일치만으로 대사를 삭제하지 않는다. 프롬프트도 이웃 문장 복사·조각 보완·없는 설명을 금지하지만, 이는 모델 준수나 의미 정확도의 보장이 아니다.
3. **세로 글자의 작은 간격이 투영에서 연결되어 수백 px 글자 높이가 됐다.** 반복되는 열 폭과 글자 성분, 또는 크기 일관성이 높은 성분 집합이 있을 때만 다시 측정한다. 채워진 사각형 잡음, 불충분한 성분, 지나치게 다른 크기는 기존 검수 경로를 유지한다. 확인된 font_cap override/strict 정책은 유지한다.
4. **가로 설정도 좁은 원문 폭에서 한 글자씩 줄바꿈될 수 있었다.** 명시적 bubble 모드와 가로 reflow에서는 넓은 검증된 내부 공간을 먼저 사용한다. 새 통합 08은 bubble 모드가 기본이다. 기존 source/strict 설정은 임의로 바꾸지 않는다.
5. **공백을 동반한 n 표기와 한 영역 번역 노드에 검사 공백이 있었다.** 일반/가는 공백이 있는 의심 표기도 공통 계약으로 거부한다. 원문의 변수 n과 수동 검수문은 유지한다. 페이지 번역의 한 번 재시도 정책도 유지한다.

말풍선 마스크가 없거나 글자를 가로지르는 경우, 서로 겹치고 포함 관계가 아닌 두 내부가 같은 성분을 소유하는 경우에는 자동으로 분할하지 않는다. 페이지 크기의 거짓 bubble 후보도 소유권 확정에 쓰지 않는다. 선택적 소유권 분석의 작업 메모리 한도를 넘으면 원래 관측을 유지한다.

같은 말풍선 안에서도 서로 다른 획인 두 원문은 유지하고, OCR/편집 여백이 이웃 원문에 들어가지 않도록 줄인다. 본문·효과음 이중 분류는 좁혀진 박스가 아닌 원래 관측 범위와 공유 획으로 검사한다. 상위 needs_review 표시가 없는 입력에서도 ambiguous_source_overlap 보존 결정은 검수 상태로 전달한다.

## 독립 이미지 실험

`tools/simulate_ownership_scenarios.py`는 사용자 자료와 별개의 글자 레이어 두 장을 먼저 만들고, 그 뒤에 일부러 겹치는 검출 관측을 만든다. 원문 정답 마스크는 처리 코드의 영역 계산에서 가져오지 않는다. 두 영역에 같은 번역문을 주어 정당한 반복 대사가 사라지지 않는지도 확인한다.

14조건: 대각선 겹침, 회색 배경, 어두운 배경의 흰 글자, 0.6배 크기, 2배 크기, 엇갈린 글자, 가로 배치, 전체/타일 중복, 컷 선·스크린톤, 저대비, +8°/−8° 기울기, 끝 조각만 겹침, 사각형만 겹치고 원문 마스크는 분리된 경우.

비교 기준은 각 크롭의 자기 원문 획 전체 포함, 이웃 원문 획 0개, 두 물리적 원문의 일대일 대응, 최종 식자 2개, 가로 출력의 과도한 한 글자 줄바꿈 방지, 새 글자 알파 밖 배경 동일성이다. 보존된 영역을 처리 성공으로 세지 않는다. 정답 배경을 입력하므로 **Qwen 복원 품질 시험이 아니다.** OCR·번역 API 응답도 통제된 입력이며 실제 RF-DETR/Hayai/vLLM 모델 정확도와 구분한다.

수정 전 v0.7.16 `02d91b3`을 별도 체크아웃에서 같은 이미지로 실행했다. 14조건 모두 OCR 크롭에 이웃 원문 픽셀이 들어갔고 12조건은 소유권 검수 표시가 있었다. 검수 표시 없이 중복 원문이 들어간 나머지 2조건도 따로 확인했다. 수정 후 14조건 모두 자기 원문 획을 전부 유지하고 이웃 원문 획은 0개였다. 각 조건에서 최종 식자 2개, 총 28영역을 처리했으며 보존을 처리로 세지 않았다. 원본·OCR 크롭·출력 접촉시트와 스크린톤 조건의 개별 이미지를 육안 확인했다. 엇갈린 열 폭을 글자 크기로 쓰던 과대평가도 이 과정에서 발견해, 39px 대신 실제 글자 성분 기준 30px로 수정했다.

```bash
python tools/simulate_ownership_scenarios.py --destination ../ownership-images
python -m pytest tests/test_source_partition_v0717.py -q --rootdir=tests --confcutdir=tests
```

## 실제 입력을 재현하는 방법

새 08의 detection 단계 `MangaDebugInspect`에서 **save_reproduction=true**를 선택하고 해당 페이지를 실행한다. 기본은 false이며 다른 단계에서는 사용할 수 없다. 보고서의 `reproduction.path`와 ComfyUI `output/manga_translator/reproduction/page_*.zip`에 저장된다.

ZIP에는 정확한 float32 원본 `original.npy`, 육안용 `original.png`, 실제 검출 마스크를 포함한 `detection.json`, 정리된 `regions.json`, 버전·개별 SHA256을 기록한 `manifest.json`이 있다. 별도의 자동 업로드나 외부 전송은 하지 않는다. 원본이 포함된 진단 자료이며 공개 저장소에 넣지 않는다. 이 자료로 같은 픽셀과 마스크를 재실행할 수 있지만, 새 모델 추론과 동일한 의미 정확도를 보장하지는 않는다.
