# 복잡한 배경·모호한 입력의 하드 검사

운영 처리 버전 **v0.7.7**을 대상으로 합니다. 이번 추가는 검사 도구·정답 생성기의 보완이며 검출/OCR/제거/식자의 운영 정책을 바꾸지 않습니다.

## 입력과 정답

imagegen으로 글자 없는 만화·직물 시장·기술 기록지 배경 3종을 새로 만들고 눈으로 확인했습니다. 각 배경의 원본 SHA와 프롬프트는 비공개 전달 자료에 남깁니다. 프롬프트를 다시 생성하는 것만으로 동일한 픽셀이 보장되지 않습니다. 동일 배경 파일과 폰트로 생성기를 실행하면 시험 입력·문장·정답 배경·마스크가 재현됩니다.

- 배경별 무글자 대조, 명확한 캡션, 그림 위 직접 식자, -12/18/90도 회전, 384px 저해상도, JPEG quality 35 + blur 0.65, 겹친 프레임의 8개 주석, 페이지 양 끝에서 잘린 글자입니다. 3배경×8변형=24입력입니다.
- 같은 기록지와 캡션에 글자/배경 차이 0/2/4/8/16/32/64/128(8비트)을 준 8입력입니다. 0은 실제 글자가 보이지 않으므로 글자 정답과 OCR 정답을 넣지 않습니다.
- 격자만 있는 대조, 격자 속 일본어 한 글자, 같은 픽셀을 Latin I 또는 비문자 선으로 해석한 2입력입니다.

총 **36입력** 중 동일 픽셀/다른 의도의 2입력은 `OBSERVATION`이며 정확도 PASS/GAP에서 제외합니다. 대표 OCR 크롭 45개 중 이 대조 1개를 제외한 44개만 채점합니다. 같은 캡션의 동일 크롭도 배경별 재현 대조로 포함하므로 일반 정확도 표본으로 확대하지 않습니다.

문장과 글자 알파는 모델 답변과 독립적입니다. 두 폰트의 문자 지원과 SHA, 모든 입력/정답 PNG·마스크 파일 SHA를 검사합니다. 회전한 테두리와 안쪽 글자의 bicubic 경계가 1px 달라질 수 있어 생성기 마스크가 두 알파를 모두 포함하도록 보완했습니다. 새 정답 검사는 서로 다른 글자의 덮어쓰기, 영역 밖 획, 손상된 정답 마스크, 보이지 않는 문장 채점을 거부합니다.

## 단계별 범위

| 검사 | 실행 | 한계 |
| --- | --- | --- |
| 실제 검출 36입력 | 고정 RF-DETR CPU + 실제 상세 검출/정리/마스크/크롭 | 잘리지 않은 글자 포함·중복·무글자 오검출 기준. 일반 검출 precision이 아님 |
| 알려진 크롭 OCR 45개 | 고정 Hayai CPU + 실제 적응형 OCR | 검출 기하와 분리한 문자 정확도. 모호한 대조 제외 |
| 실제 검출 후 연계 36입력 | 위 실제 RF 원출력 → 실제 크롭/OCR/수집/편집 계획/단색 제거/가능한 식자 | 번역 생성과 수동 GUI 검수를 제외하고 고정 한글 시험 문장을 명시적으로 입력. 실제 Qwen 필요 시 대기하며 정답 배경을 주입하지 않음 |
| 알려진 기하 제거 36조건 | 정답 영역/마스크로 실제 단색 제거·타일 계획 | 검출 정답을 제공한 분리 검사. 정답 배경은 채점에만 사용 |
| 분리 식자 72조건 | 같은 입력에 기본/2배 고정 시험 문장·실제 폰트·회전 배치 | 이 단계만 정확한 정답 배경을 입력. Qwen 제거 성공으로 계산하지 않음 |

연계 검사는 실제 OCR이 수집한 문장과 영역을 그대로 사용합니다. 독립 정답으로 OCR 원문을 교정하지 않습니다. 비문자에 수집된 편집 대상, 잘린 원문의 수집, 공백을 제외해도 틀린 원문 수용, 그림 픽셀의 새 손상, 합성 밖 픽셀·보호 픽셀·알파 충돌을 구분합니다. 큰 혼합 크롭과 부분 크롭에는 단일 원문 정답을 억지로 지정하지 않습니다.

수집된 원문을 고정 시험 문장으로 교체하도록 허용한 후단 검사이며, 운영 GUI에서 사람이 원문을 확인·승인하는 과정이나 실제 번역 서버를 재현한 결과는 아닙니다. Qwen을 기다리는 계획·가독성 정책의 중단·원본 보존을 전체 페이지 완료로 합산하지 않습니다. 잘린 문장은 완전한 OCR 정답에서 제외하고 원문 보호 여부를 따로 검사합니다.

## 재현

전달 자료의 `backgrounds`에는 세 PNG와 `assets.json`이 있습니다. 임의의 다른 배경을 사용할 수 있지만 이번 실행을 재현하려면 같은 SHA의 배경이 필요합니다. 생성 이미지·크롭·결과는 Git에 넣지 않습니다.

```bash
python tools/stress_ambiguous_pages.py --mode generate --assets /path/to/backgrounds --destination ../hard-results
python tools/stress_ambiguous_pages.py --mode contracts --destination ../hard-results
python tools/stress_ambiguous_pages.py --mode detector --models /path/to/models --destination ../hard-results
python tools/stress_ambiguous_pages.py --mode known-ocr --models /path/to/models --destination ../hard-results
python tools/stress_ambiguous_pages.py --mode chain --models /path/to/models --destination ../hard-results
```

검출과 알려진 크롭 OCR은 독립 실행할 수 있습니다. 연계 모드는 완료된 실제 검출 보고서의 입력·소스 SHA가 같아야 합니다. 매 모드는 실행 소스·모델 revision·실제 호출·완료 여부를 기록합니다. 이미 있는 보고서를 묵시적으로 덮어쓰지 않습니다. 종료 코드 1은 관측 GAP, 2는 실행 오류입니다.

실제 Qwen 배경 생성·네이티브 ComfyUI 실행기·GUI 승인·GPU 동등성·일반 손글씨/모든 이미지의 정확도는 이 검사로 보증하지 않습니다.

## 이번 실행의 관측

실제 RF-DETR는 36입력 중 **27 PASS / 7 GAP / 의도 대조 2개**, 실제 기본 OCR은 **10개 정확 일치 / 34개 미일치 / 의도 대조 1개**였습니다. 채점한 44크롭 조건의 고유 PNG는 29종입니다. 같은 픽셀의 6개 반복 그룹은 모두 같은 OCR을 반환했습니다. 결과가 갈리는 원인을 모두 무작위성이나 모호함으로 설명할 수 없으며, 선명한 같은 글자의 반복 누락도 확인됐습니다.

실제 검출 후 연계의 채점 34입력은 **단계 끝까지 실행 14 / Qwen 대기 17 / 명시적 중단 3**입니다. 독립 원문·제거·식자를 모두 만족한 글자 입력은 격자 속 한 글자 1개이며, 올바르게 원본 유지한 무글자 대조는 4개입니다. 단계 끝까지 실행된 14개를 품질 합격으로 세지 않습니다. 기본 연계의 7 PASS는 해당 안전/수집 기준만 충족한 수치이며, 미검출로 편집이 없는 저대비 입력도 있어 전체 완료와 다릅니다.

글자 없는 직물 시장에서 6개 비문자 영역을 OCR 수집/편집 대상으로 받았고, 글자를 추가한 같은 배경에서도 비문자 오검출이 남았습니다. 만화의 잘린 왼쪽 문구도 편집 대상으로 수집됐습니다. 이 사례들은 Qwen 대기이며 실제 Qwen 결과나 최종 그림 손상을 확인한 것은 아닙니다. 실행한 단색 제거·부분 base에서는 독립 글자 밖의 새로운 그림 손상 픽셀은 관측되지 않았습니다.

알려진 기하의 108분리 조건은 **85 PASS / 17 GAP / 의도 대조 6개**입니다. 채점 제거 34조건의 상태는 실제 단색 완료 10 / Qwen 대기 16 / 잘린 원문 보존 3 / 빈 입력 5입니다. 채점 식자는 실제 글자 출력 41 / 무처리 10 / 중단 17입니다. 17중단 중 8개는 2~16/255의 저대비 근거 부족, 9개는 길이/회전 공간 제한입니다. 같은 회전 입력 3개에 별도의 짧은 고정 문장을 넣으면 모두 조판돼, 긴 시험문장의 거부를 전부 코드 결함으로 계산하지 않습니다.

### OCR 입력 예산의 비교

기본 적응형 OCR과 똑같은 44크롭 모두에 하나의 비교 설정을 적용했습니다.

| 조건 | 정확 일치 | 공백 제외 내용 일치 |
| --- | ---: | ---: |
| 현재 기본 설정 | 10 / 44 | 10 / 44 |
| base_patches=256, small_text_patches=512, small_text_px=8, line_split=True | 40 / 44 | 40 / 44 |
| 같은 예산, line_split=False | 28 / 44 | 40 / 44 |

기본에서 맞았던 조건이 비교 설정에서 틀린 경우는 이 표본에 없고, 30조건이 개선됐습니다. 남은 4조건은 90도 회전 3개와 대비 2/255 1개입니다. 행 분리를 끄는 조건의 일부 불일치는 일본어 행 경계의 공백 차이입니다. 검증된 OCR 행 계획은 line_split=False를 허용하지 않으므로 이를 모든 운영 입력에 바로 적용할 설정으로 제시하지 않습니다.

같은 실제 검출 원출력을 쓰는 별도 4입력 연계에서도 작은 예산으로 명확한 만화 캡션은 원문 인식→실제 단색 제거→식자를 만족했습니다. 직물 배경의 비문자 수집과 잘린 문구 수집은 남았습니다. 운영 기본값과 기존 실행의 GAP을 바꾸지 않았고, 비교 설정으로 전체 이미지 문제가 해결됐다고 계산하지 않습니다.

같은 관측 후보 집합에 score 후필터 0.5/0.7/0.9를 준 별도 분석에서는 정답 글자가 없는 크롭이 19→10→2→0개로 줄지만 빠진 원문 영역은 8→17→33→64개로 늘었습니다. 이는 모델 재추론 없이 고정 후보 집합을 실제 후처리한 분석이며 새 임계값으로 상세 검출/경계 복구부터 재실행한 결과가 아닙니다. 임계값을 올리기만 해서는 두 문제를 동시에 해결하지 못했습니다.

전체 CPU 회귀는 **776 PASS**입니다. 기본 4모드는 동일 운영/검사 소스 SHA로 완료됐고, 실제 RF 호출 64회, 알려진 크롭 OCR 생성 66회, 검출 후 OCR 생성 141회를 기록했습니다. 별도 설정 비교/원인 분리의 호출과 혼합하지 않습니다. 이미지·배경·원출력·비교 스크립트와 보고서는 비공개 전달 자료에 포함하며 저장소에는 생성/검사 코드와 이 관측만 넣습니다.
