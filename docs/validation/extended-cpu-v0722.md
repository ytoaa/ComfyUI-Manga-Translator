2026-10-30 한국시간. 기준 c5dfe83. 제품 런타임 코드는 변경하지 않고,
이전에 실행하지 않은 일부 조합과 사용 규모를 추가했다.

메모리는 Linux getrusage(RUSAGE_SELF).ru_maxrss로 측정한다. 이 환경에서
/proc 기반 psutil 값이 약 2 MiB로 관측되어 신뢰할 근거가 부족했다.
그 값을 메모리 안정성의 증거로 채택하지 않고 커널 호출로 다시 실행했다.
ru_maxrss는 순간 상주 메모리가 아니라 실행 중 최대값이며, 장시간 누수 부재를
증명하지 않는다. 반복 입력은 고정 320×120 이미지와 같은 캐시 키다.

새 테스트의 최초 실패에는 시험 자체의 두 오류가 있었다. 원본 보존을 편집
영역 밖까지 비교해 원본/clean의 양자화 차이를 결함으로 간주했고, 존재하지 않는
artifact helper를 호출했다. 보호 사각형 안의 원본 픽셀을 정확 비교하고 모든
저장 artifact를 독립 SHA-256으로 확인하도록 바로잡았다. 제품의 소유권이나
최소 크기 제한을 완화하지 않았다.

## 재현

```sh
OMP_NUM_THREADS=4 python -m pytest tests/test_extended_cpu_validation.py -q --rootdir=tests --confcutdir=tests --tb=short -o junit_family=legacy --junitxml=/tmp/extended-cpu.xml
```

OpenSSL CLI와 기존 CPU 테스트 의존성을 사용한다. 메모리 시험은 Linux에서만
실행한다. 실제 ComfyUI·GPU·운영 모델은 호출하지 않는다.

## 결과

**83 PASS / 0 FAIL / 0 ERROR / 0 SKIP**, 54.438초.
72조합의 성공/보존/거부를 엄격히 구분한 재검사도 72 PASS였다.
1,500회 반복 구간은 48.530초이며, 워밍업 후 최대 메모리 증가량은
2,318,336바이트(2.211 MiB)였다. 이 한정된 실행에서는
설정한 48 MiB 증가 상한·임시 파일·픽셀/세대 검사에 위반이 없었다.
제품 코드에서 새로운 결함은 확인하지 못해 런타임 버전은 v0.7.22로 유지했다.
정확한 사례·시간·메모리 표본은 extended-cpu-v0722.json에 보관한다.
