# 페이지 실패 상황 시뮬레이션

검출 누락, 다단 크롭 혼합, OCR 오독, 보존 영역과 여백 충돌을 반복해서 평가하기 위한 개발 도구입니다. v0.7.4에서 추가했으며 v0.7.5의 수정 전후에도 같은 기준을 사용합니다. 기존 합성 그래프의 모델 정답 대역과 실제 모델 품질을 분리하고, 정상 종료를 글자 인식 성공으로 계산하지 않습니다.

사용자가 제공한 이미지·크롭·OCR 원문을 입력으로 사용하거나 저장소에 복사하지 않습니다. `tools/image_scenarios.py`가 새 문장과 도형으로 페이지 6종, OCR 크롭 15종을 만듭니다. 동봉 폰트의 문자 지원을 먼저 확인하므로 빠진 글리프를 사각형으로 그린 뒤 정답이라고 부르지 않습니다. seed, 생성기·폰트·입력 SHA256을 기록합니다. 결과 경로는 Git 체크아웃 밖이어야 합니다.

## 검사 구분

| 실행 모드 | 입력·추론 | 평가 대상 |
| --- | --- | --- |
| `contracts` | 인공 픽셀과 명시적 검출/OCR 응답 대역, 실제 운영 노드·폰트 코드 | 경계값·정책 전이·실패 전파. 모델 정확도 아님 |
| `detector` | 고정 RF-DETR 실제 CPU 추론 + 실제 영역 정리·마스크·크롭 | 생성 정답 획의 누락, 중복 입력, 열 혼합, 빈 페이지 오검출 |
| `ocr` | 정답을 알고 생성한 완전한 크롭, 고정 Hayai 실제 CPU 추론 + 실제 적응형 OCR | 철자 일치와 CER. 검출이 해당 크롭을 찾았다는 뜻은 아님 |
| `summary` | 실행 JSON 집계 | 모드별 PASS/GAP/ERROR. 미실행·중간 중단은 따로 표시 |

`PASS`는 해당 행의 명시한 기준을 만족했다는 뜻입니다. 너무 긴 번역문을 거부하거나 미검증 90도 입력에 대해 수평 보정을 인증하지 않는 **의도된 중단·기권**도 포함합니다. 전체 번역 페이지 성공 수가 아닙니다. `GAP`은 목표 미충족이며, 이미 알려진 실패라도 PASS로 바꾸지 않습니다. `ERROR`는 예기치 않은 도구·실행 오류입니다. 종료 코드는 각각 **0=미충족 없음, 1=GAP 있음, 2=ERROR**입니다.

### 단계별 55조건

| 상황 | 조건 수 | 독립적으로 확인하는 내용 |
| --- | ---: | --- |
| 검출 경계 | 5 | 94/96.4/97.9/98/100% 지원 범위, 98% 판정 전이와 미복구 원문 보존 |
| 크롭 여백 | 12 | 보존 영역과 간격 0/4/12/13px × OCR/편집 여백 조합. 정규화 좌표 반올림 경계 포함 |
| 다단 문서 | 5 | 사이드바·배경 잡음·자동 기하 보정에 따른 열 혼합·본문 누락 |
| OCR 수용 정책 | 6 | 정답, 한 글자 누락, 무관한 문장, UNK, 빈 답변, 반복 답변. 이 모드의 응답은 대역 |
| 겹친 식자 | 12 | 처리 순서 × 가로/세로 RTL × 번역 길이. 완전한 문자열, 실제 글자 알파 비충돌, 알파 밖 픽셀 보존 |
| 회전 입력 | 4 | -17/0/13.5/90도. 지지된 기울기 보정과 미인증 경로 구분 |
| 이미 잘린 획 | 3 | 잘린 글자에 검토 상태를 붙이며 온전한 OCR 행으로 인증하지 않음. 보이지 않는 문자의 CER은 계산하지 않음 |
| 캐시와 식자 | 4 | 작은 텐서에 저장 한도 64B/1MiB를 주입. 저장 생략 후 값·진단 전달, 정상 식자와 충돌 거부를 각각 확인 |
| 배경 제거 | 2 | 실제 균일 배경 제거, 무늬 배경의 미생성 Qwen 타일 거부. 가짜 생성 결과 없음 |
| 빈 페이지 | 2 | 진짜 빈 페이지와 응답 대역이 놓친 글자 페이지를 같은 정상 종료로 합산하지 않음 |

크롭의 합집합이 정답 획을 덮는 것만으로 통과시키지 않습니다. 생성한 각 글자 영역의 획 98% 이상 보존, 중복 입력 획 비율 1% 이하, 서로 다른 본문 열의 혼합 없음, 실제 빈 페이지에 크롭 없음의 조건을 함께 평가합니다. 일반 이미지의 검출 precision이나 확률적 신뢰도는 아닙니다.

OCR 정답은 모델 답변과 독립적인 생성 원문입니다. NFKC와 공백 정규화 후 대소문자·구두점을 유지해 edit distance/CER·완전 일치를 계산합니다. 줄바꿈 영향을 볼 수 있도록 공백을 제외한 보조 CER도 기록합니다. 틀린 응답이 품질 검사를 통과한 경우 `accepted_by_contract=true`와 `GAP`이 동시에 남습니다.

## 재현

Git 체크아웃 또는 개발 source ZIP과 별도의 CPU 개발 환경을 사용합니다. 실행 ZIP에는 개발 도구가 포함되지 않습니다. 운영 ComfyUI의 torch/CUDA를 교체하지 않습니다. 실제 모델은 [CPU 모델 관측](cpu-models.md)의 고정 bundle을 `/path/to/models/hayai`와 `/path/to/models/detector`에 준비합니다. 모델 모드는 다운로드하지 않고 파일 SHA256을 검증한 로컬 가중치만 사용합니다.

```bash
# 결과는 저장소 밖에 둡니다. 아래 명령은 각각 실행합니다.
python tools/simulate_page_failures.py --mode generate --destination ../scenario-results
python tools/simulate_page_failures.py --mode contracts --destination ../scenario-results
python tools/simulate_page_failures.py --mode detector --models /path/to/models --destination ../scenario-results
python tools/simulate_page_failures.py --mode ocr --models /path/to/models --destination ../scenario-results
python tools/simulate_page_failures.py --mode summary --destination ../scenario-results
```

GAP이 있으면 앞 명령이 종료 코드 1을 반환하므로 `&&`로 묶으면 뒤의 실제 모델 검사를 실행하지 않습니다. `detector`의 `--include-sfx`는 선택 범위를 바꾸는 별도 진단입니다. 기본/효과음 포함 비교는 서로 다른 결과 디렉터리에서 실행해야 원래 보고서가 유지됩니다. `--threads`는 1–8, 기본은 4입니다. 생성기를 수정했다면 `--mode generate`로 입력·정답을 함께 다시 만듭니다.

각 모드 JSON은 실행 중 갱신되며 마지막에만 `completed=true`가 됩니다. 원문 응답·오류·재시도 진단·입력 해시·모델 revision·실제 호출·CPU 환경·소스 파일 해시를 보존합니다. `detector-artifacts`에는 실제 검출 결과와 OCR 크롭 위치 미리보기가 남습니다. 생성물·가중치·실제 사용자 입력은 커밋하지 않습니다.

## v0.7.4 수정 전 CPU 관측 · 2026-10-19

torch 2.6.0+cpu, RF-DETR 1.7.0, Transformers 5.1.0, CPU 4스레드로 실행했습니다. 고정 모델 revision과 bundle SHA 검증은 기존 어댑터를 사용했습니다. 세 모드의 실행 소스 해시를 대조하며, 각 모델 결과는 별도 JSON에 보존합니다.

| 구분 | 조건 수 | PASS | GAP | ERROR |
| --- | ---: | ---: | ---: | ---: |
| 단계별 상황 재현 | 55 | 43 | 12 | 0 |
| 실제 검출·크롭 | 6 | 4 | 2 | 0 |
| 실제 OCR·생성 정답 비교 | 15 | 9 | 6 | 0 |

55조건의 미충족은 크롭 여백 충돌 6조건, 사이드바가 있는 다단 혼합 3조건, 잘못된 OCR 응답 수용 2조건, 글자를 놓친 검출 응답과 진짜 빈 페이지의 구분 1조건입니다. 12개의 서로 다른 결함이나 일반 페이지 실패율로 확대하지 않습니다. 캐시 한도를 작게 주입한 4조건에서는 값·보고서가 그대로 전달됐으며 정상 식자와 충돌 거부가 각각 유지됐습니다.

실제 RF-DETR 문단 페이지에서는 정답 글자가 모두 크롭에 포함됐지만 정답 획 약 29.3%가 중복 입력 영역에 들어갔습니다. 다단 페이지는 마지막 본문 단락과 사이드바를 놓쳤고 중복 획도 약 14.7%였습니다. 두 조건 모두 GAP입니다. 합집합의 글자 포함률만 사용하면 앞 조건을 잘못 통과시킵니다.

실제 Hayai는 보통/작은 크기의 소문자 영어, 작은 일본어, 두 줄 문단, 90도 회전 Latin, 가로 중국어에서 정답과 달랐습니다. 예를 들어 생성 정답 `今天下午我們一起去看電影。`에서 `影`를 빠뜨린 답변도 휴리스틱 검사는 통과했습니다. 이 입력들의 일반 OCR 정확도나 다른 폰트·GPU의 오류율을 뜻하지 않습니다. 15종 중 정확히 일치한 9종과 미충족 6종을 그대로 기록합니다.

평가 도구의 회귀는 15개이며, 중복 크롭·열 혼합·빈 페이지 오검출·화면 밖 좌표를 거짓 통과시키지 않는지, 미완료/이전 실행 결과를 완료로 표시하지 않는지도 검사합니다. 기존 검사를 포함한 전체 회귀는 **738 PASS (108.98초)**입니다. 이 수치는 위 모델 품질 GAP을 해결했다는 뜻이 아닙니다. 운영 처리 코드·08 그래프·캐시 버전은 변경하지 않았습니다.

## v0.7.5 수정 후 CPU 관측 · 2026-10-19

같은 55조건과 실제 모델 입력·정답·기준으로 다시 실행했습니다. 3개 모드의 소스 파일 해시가 같고 모두 completed=true입니다.

| 구분 | 조건 수 | PASS | GAP | ERROR |
| --- | ---: | ---: | ---: | ---: |
| 단계별 상황 재현 | 55 | 52 | 3 | 0 |
| 실제 검출·크롭 | 6 | 4 | 2 | 0 |
| 실제 OCR·생성 정답 비교 | 15 | 9 | 6 | 0 |

여백 6조건과 사이드바가 있는 다단 3조건이 개선됐습니다. 남은 정책 GAP 3조건은 철자 누락·무관한 정상 문장의 수용 2조건과 검출 누락/진짜 빈 페이지 구분 1조건입니다. 실제 검출의 중복 크롭·누락과 실제 OCR의 철자 차이는 그대로 GAP입니다. 검사 기준을 완화하거나 정답 문장을 운영 OCR에 넣지 않았습니다.

추가 회귀는 원문 교차 보존/strict 중단, 실제 소수 좌표와 왕복 오차 구분, 사이드바 유지, 영역 도중 실패 시 앞 행 폐기, 모델 실행 오류 전파, 겹친 편집 영역 보존, 최종 PNG 원본 일치와 폴더 needs_review 수집을 검사합니다. 전체 회귀는 **754개**입니다. 검토 대상으로 보존한 영역을 번역 완료로 세지 않습니다.

비공개 원본 8장도 다시 확인했습니다. 기존 실제 검출 124회의 동일 입력·임계값 결과를 재사용해 현재 후처리·크롭을 실행했고 실제 OCR 115회에 해당하는 결과를 수집했습니다. 최종 경계가 같은 7장은 크롭·행 계획·명세의 의미를 대조하고 진단 경로 차이만 허용해 같은 출력을 최종 명세로 수집했습니다. 경계가 바뀐 3단 문서는 재추론했습니다. 원본의 많은 중국어·영어 오독, 장식 표지·작은 본문 검출 누락은 남았습니다. 두 이미지의 단색 제거·식자는 수동 한국어와 수동 보존을 사용한 부분 진단이며 전체 자동 성공이 아닙니다.

## 남는 범위

검출기는 명시적 CPU 진단 방식으로 로드합니다. 생산용 CUDA 로더 정책이나 운영 노드를 CPU fallback으로 바꾸지 않습니다. 인쇄체·단순 도형·고정 잡음은 실제 만화의 손글씨, 복잡한 효과음, 그림 배경 전체를 대표하지 않습니다. 이 자료는 이전 비공개 8장 검사와 함께 사용해야 하며 인공 사례 통과만으로 그 이미지들을 해결했다고 판정하지 않습니다.

번역 서버, Qwen 실제 배경 복원, ComfyUI 실행기, GPU 결과 동등성은 이 도구의 검증 범위 밖입니다. 무늬 배경에 필요한 Qwen 타일을 정답 배경으로 대신 넣어 전체 성공을 만들지 않습니다. 비공개 이미지는 저장소에 넣지 않습니다.
