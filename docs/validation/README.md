# 검증 범위

검증 대상 처리 버전은 **v0.7.1**입니다. 실행 성공률·계약 검사·모델의 인식 정확도를 구분합니다.

## v0.7.1 경계 수정 검증 · 2026-10-19 KST

아래 v0.7.0 추가 감사에서 실패한 경계를 수정했습니다. 전체 CPU 회귀 **669개**, 추가 수용 시나리오 **63개: PASS 45 / FAIL 0 / OBSERVED 18 / ERROR 0**을 검사합니다. PASS는 계약·기하·장애 처리 통과이며 OCR 의미 정확도가 아닙니다. 기존 660개에 페이지/프로젝트 교정 분리, 진단 변경과 내용 충돌, legacy 교정 안내, lazy 캐시 값·진단 보존, 빈 크롭과 부분 페이지 보호, 한 페이지 교정 뒤 프로젝트 재실행, 두 번째 탭 차단 후 첫 티켓의 실제 결과 수집까지 9개 회귀를 추가했습니다.

공통 처리 revision과 페이지 교정 revision을 분리했고, 재개할 때마다 저장된 페이지의 revision을 비교합니다. 교정 소유권 없는 이전 JSON은 삭제하지 않고 충돌을 안내합니다. 새 통합 08은 입력 상태를 검수 노드의 page_context_json에 연결합니다. 같은 내용 revision의 UI 재표시는 보류 편집을 유지합니다. 문단별 텍스트 한도는 제거·식자 준비에서 같은 검증 함수를 사용합니다.

실제 두 OCR 모델의 고정 가중치와 같은 행 입력으로 CPU 관측을 반복했습니다. 원문 행의 오독은 남아 있습니다. 완전한 흰색 OCR 크롭은 이제 모델을 호출하지 않고 empty_crop 진단을 반환하며, 수집 단계는 해당 영역을 원본 보호·검수로 넘깁니다. 같은 페이지의 나머지 정상 원문은 유지합니다. 잘못된 행 계획은 빈 크롭이어도 거부합니다. 18개 관찰 중 14개는 모델 추론이고 4개는 빈 크롭/점 문장부호의 검증된 생략 경로입니다.

재현 도구의 report.json에는 기준 HEAD와 별도로 실행한 소스별 SHA256·작업 트리 변경 여부를 기록합니다. 변경 작업 트리의 결과를 이전 커밋 자체의 검증으로 표기하지 않습니다. 모델/큐 대역과 실제 CPU 폰트·두 OCR 엔진의 범위는 아래 v0.7.0 감사와 같으며, GPU 전체 실행·실제 번역 서버·Qwen 의미 품질·실제 ComfyUI 두 브라우저 E2E는 이번 수정에서도 직접 검증하지 않았습니다.

## v0.7.0 추가 경계 검증 · 2026-10-18 UTC

운영 기준 커밋은 `fdeaa0661f5979fec91eae10cf5db2d9958a5056`입니다. 당시 운영 코드를 수정하지 않고 기존 CPU 회귀를 다시 실행해 **660 passed in 70.37s**를 확인했습니다. 추가 수용 시나리오는 **63개: PASS 35 / FAIL 10 / OBSERVED 18 / ERROR 0**이었습니다. 기존 회귀 통과와 아래 실패는 함께 유효했던 v0.7.0의 관측입니다. 현재 수정 결과는 위 v0.7.1 항목과 구분합니다.

실패 10건은 아래 9가지 문제로 묶입니다. 빈 크롭 검사는 엔진별로 한 건씩입니다.

| 경계 | 재현된 동작 | 필요한 구조 변경 |
| --- | --- | --- |
| 다른 페이지에 같은 OCR 문서 | 페이지 구분 없이 같은 교정이 적용됨 | 교정 키를 프로젝트·페이지·영역으로 분리 |
| 진단 정보만 변경 | 저장된 교정이 출력에 적용되지 않고 충돌 안내도 없음 | 내용 revision과 진단을 분리하고 교정 충돌을 명시 |
| 설정 변경 후 일부 처리·중지·재개 | 남은 이전 설정의 완료 페이지를 선택하지 않음 | 페이지별 처리 revision을 지속적으로 비교 |
| 두 탭에서 같은 프로젝트 시작 | 두 번째 실행은 중단되지만 첫 실행의 run_id를 덮어씀; 페이지 시도는 1개 | 실행 소유권 확인 후 상태 변경 |
| 한 페이지의 교정 | 전체 프로젝트 workflow fingerprint가 바뀜 | 페이지 교정과 공통 설정의 무효화 범위를 분리 |
| 실행 출력 재표시 중 미확정 편집 | 화면은 이전 번역으로 바뀌고 저장 위젯에는 새 교정이 남음 | 표시 상태와 보류 중 편집의 병합 규칙 |
| 캐시 확인 후 파일 제거 | 사용 시점에 Checkpoint input unavailable로 중단 | 캐시 세대 보존 또는 제한된 재계산 |
| 문단마다 1,100자 입력 | 두 문단은 허용되지만 합친 2,202자가 식자 준비 단계의 2,048자 제한에 걸림 | 문단·부모 문서의 예산 계약 통일 |
| 완전한 흰색 OCR 크롭 | quality_guard=True에서도 Hayai는 Princi, Manga OCR은 それは、를 원문으로 수용 | OCR 이전 빈 크롭 판정과 인식 근거 검사 |

설정 변경·재개와 두 탭 검사는 실제 프로젝트/attempt 파일과 운영 컨트롤러를 사용하고 ComfyUI 큐·이력만 대역으로 넣었습니다. 한 페이지 교정 검사는 fingerprint의 변경까지 확인했으며 실제 책 전체를 재번역하지 않았습니다. UI 검사는 실제 node_ui.js와 DOM/event 대역을 사용했습니다. 사용자 ComfyUI와 연결한 두 브라우저 E2E 결과는 아닙니다. 교정 미적용·UI 불일치는 저장된 교정 자체가 삭제됐다는 뜻이 아닙니다.

통과 항목에는 캐시 픽셀 무손실·손상 감지·저장 공간 오류 시 계산 결과 보존, 동일 파일명의 모델 교체 감지, 잘못된 다운로드 SHA/DNS 오류/중단의 임시 파일 정리, 삭제된 결과 감지, 오류 이력의 완료 오판 방지, 실제 폰트의 가로·세로·회전 식자가 포함됩니다. 302개 이미지의 목록·중복 파일명·순서도 확인했으나 302페이지 전체 번역은 실행하지 않았습니다. 256개 교정 revision 제한 초과 거부는 명시된 제한의 통과이며, 대형 프로젝트 교정을 지원한다는 의미가 아닙니다.

실제 OCR은 CPU torch 2.14.1, transformers 5.1.0, 4스레드, max_new_tokens=256에서 고정 revision과 SHA256 검증을 마친 Hayai v2와 Manga OCR을 각각 실행했습니다. 동일 프로필 이미지의 회전 보정된 5행과 합성 한글/영문/흰색 크롭을 비교했습니다. 원본은 검수 표시가 있는 사용자 이미지이며 깨끗한 원본 벤치마크가 아닙니다. 18개 OBSERVED 중 2개 점 문장부호 입력은 기하 검증 경로로 처리되어 모델을 호출하지 않았습니다. 정상 종료를 인식 정확도 통과로 세지 않습니다.

| 동일 입력 | Hayai v2 | Manga OCR |
| --- | --- | --- |
| 프로필 제목 행 | MY PROFILE | MYPRのPLEC |
| 일본어 본문 행 | クラスはアサシンのサーヴァントなんだ☆ | ううんは、アサシーのヤーヴァントなんだか |
| 합성 한글: 선생님, 안녕하세요. | 선생님, 안녕하세요. | 2015年19月14日- |
| 합성 영문: LEVEL 2 / TEST | LEVEL 2/TEST | LENEL2/TESTT |
| 완전한 흰색 크롭 | Princi | それは、 |

이 표로 일반 모델 순위나 정확도 비율을 확정하지 않습니다. 흰색 **OCR 크롭** 실패는 검출 영역이 없는 **빈 페이지**의 통과 경로와 별개입니다. 실제 RF-DETR/GPU 메모리 부족, 번역 서버, Qwen 제거 품질, 사용자 ComfyUI 전체 실행은 이번 추가 검사에서 실행하지 않았습니다.

재현 도구는 tools/audit_boundaries.py입니다. 기본 실행은 모델 없이 43개 계약·폰트·장애 주입 검사를 수행합니다. 실제 OCR까지 실행하려면 개발 환경의 transformers/tokenizers/safetensors, 고정 모델 폴더와 같은 행 입력이 필요합니다.

```bash
python tools/audit_boundaries.py --destination validation/boundary-audit
python tools/audit_boundaries.py --actual-ocr --models /path/to/models --row-inputs /path/to/rows --destination validation/boundary-audit-models
```

행 입력 파일명은 actual-row-0.png부터 actual-row-4.png까지입니다. 도구는 입력별 SHA256, 모델 revision, 응답, 실패 증거를 report.json에 저장합니다. FAIL 또는 ERROR가 있으면 종료 코드 1이며 이는 발견한 문제를 숨기지 않기 위한 동작입니다. 사용자 이미지·가중치·생성 보고서는 공개 Git에 넣지 않습니다.

## 저장소 정리 확인 · 2026-10-18

로컬에서 등록 파일 121개(자기 자신인 SHA256SUMS 제외), 로컬 문서 링크 61개, 현재 어댑터 출처 해시와 통합 GUI/API 쌍을 검사했습니다. 통합 08의 60개 노드 API 그래프와 운영 Python 코드는 정리 전과 같습니다. 합성 식자 자료는 새 지정 경로에 재생성됐고, 캔버스 프런트엔드 검사가 통과했습니다.

실행 ZIP 67개/개발 source ZIP 122개 파일의 무결성과 파일별 SHA256을 확인했습니다. 실행 ZIP의 전체 노드를 추출·import하는 회귀와, 테스트/과거 기록은 source ZIP에만 포함되고 저장소 체크섬은 패키징으로 바뀌지 않는 조건도 통과했습니다. GitHub Actions 설정은 같은 검사 경로로 정리했으며, 이번 수치는 로컬 실행 결과입니다. 실제 모델 추론은 이번 정리에서 다시 실행하지 않았습니다.


## v0.7.0 구조·UI 검사

공통 문서의 좌표/수정 출처, 입력 revision별 교정, 원문 수정 뒤 번역 무효화, 문단 ID 응답 순서, 제목/본문의 글줄 높이 근거, 실제 한글 폰트의 회전 frame, 페이지 밖 glyph 거부, 보호 픽셀과 이웃 충돌을 검사합니다. 같은 합성 그래프의 재실행과 폰트 변경에서 검출/OCR/Qwen 재호출이 없는 조건을 확인합니다. 모델 응답 대역을 쓴 이 검사와 실제 OCR 관측은 별개입니다.

모델 파일이 같은 이름으로 바뀌면 캐시 키가 달라지고, 손상/불완전 캐시는 miss가 됩니다. 원자 다운로드의 재사용·잘못된 SHA256·수정된 기존 폴더 보존, 확정 이전 페이지의 artifact hash·언어·문맥 예산, 실행 중 프로젝트의 설정 변경 거부도 검사합니다.

`check_canvas_frontend.cjs`와 `check_node_ui.cjs`에서 캔버스 연속 Run/중지/재연결 및 문단 편집·확정·revision 분리·텍스트 escaping·모델 진행·UI 위젯 비직렬화를 확인했습니다. 별도 Chromium에서 실제 node_ui.js DOM을 렌더링하고 textarea 편집·확정 버튼·다운로드 표시를 실행했습니다. 전체 ComfyUI 앱과 사용자 브라우저를 연결한 E2E 검증은 아닙니다.

캐시된 제거 결과의 잔존 원문 진단 보고서도 함께 보존하며, 재사용 시 Qwen을 다시 실행하지 않고 PreviewAny에 전달합니다. lazy 보고서 연결까지 포함한 그래프 순환 검사도 수행합니다.

최종 실행 ZIP은 75개, 개발 source ZIP은 132개 파일입니다. 등록 파일 131개(자기 자신인 SHA256SUMS 제외), 로컬 문서 링크 68개, 어댑터 출처 해시, 통합 GUI/API 쌍과 빌더 재현성을 확인했습니다. ZIP의 전체 노드 import·파일별 무결성 회귀를 통과했습니다. 위 저장소 정리 확인 수치는 이전 v0.6.4 작업의 기록입니다.
