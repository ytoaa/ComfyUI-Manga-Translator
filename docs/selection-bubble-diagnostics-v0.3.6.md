# 표지 검출 선택·실제 말풍선 제약·OCR 실패 구분 (v0.3.6)

`git pull` → ComfyUI 재시작 → **새 08 JSON을 다시 불러오기**.

## 표지 글자가 나오지 않을 때

첨부한 800×1125 표지에는 큰 흰 장식 글자가 있지만, 실제 검출 JSON은 제공되지 않았다.
따라서 검출 모델의 누락인지, `onomatopoeia` 분류 후 제외된 것인지는 아직 확정하지 않는다.

- 새 08 왼쪽의 **효과음·표지 큰 글자 포함 · 공통 스위치**는 기본 `PrimitiveBoolean`이다.
  검출·영역 선택·제거 마스크의 `include_sfx`에 같은 값을 연결해 세 곳이 어긋나지 않게 한다.
  기본값 false는 유지한다. 표지 장식 글자가 효과음 분류로 제외됐다면 true로 바꿔 포함할 수 있다.
  모든 장식 글자가 반드시 효과음으로 분류되거나, 이 스위치만으로 검출된다는 뜻은 아니다.
- 전체/상세/경계 복구 호출의 원래 label별 수, 선택한 글자 수, 제외한 효과음 수를
  `Manga detection selection` 로그와 `region_resolution.detection_audit`에 남긴다.
  호출 간 중복이 포함된 원시 개수이며 고유 문단 수와는 다르다.
- 영역 0개이면서 제외된 효과음이 있으면 `needs_review=true`,
  `no_text_reason=excluded_onomatopoeia_present`를 JSON에 표시한다.
  의도적으로 제외된 후보가 있다는 뜻이며, 그 후보가 실제 문자임을 보증하지 않는다.
- native 1152 범위 안의 이미지도 선택 글자가 0개이고 한 변이 576보다 크면
  auto 모드에서 작은 576 창을 추가 검사한다. 동일한 전체 창은 반복하지 않는다.
  기존 총 창 제한과 미해결 경계 중단은 유지한다. 진짜 빈 페이지도 검출 호출이 늘 수 있으나
  OCR/번역/Qwen 생략과 원본 저장 동작은 유지한다.

실제 표지 GPU 검출/OCR 성공은 아직 확인하지 않았다. 큰 장식 글자, 색 배경,
회전 문자에 대한 검출 모델 자체의 한계도 남는다.

## 번역문이 말풍선을 벗어나는 문제

이전 식자는 주로 사각형 프레임 안에 들어가는지를 검사했다.
뾰족하거나 오목한 말풍선은 사각형 모서리가 말풍선 밖일 수 있어 충분하지 않았다.

새 08은 `MangaLetterPlan.respect_bubbles=true`다.

1. 직접 연결한 내부 마스크가 있으면 우선 사용하고, 없으면 RF-DETR의 실제 bubble mask를 사용한다.
2. 여백이 붙은 편집 사각형의 중심 대신 **원문 획의 포함률**로 소유 말풍선을 찾는다.
   원문 획의 95% 이상을 포함하는 마스크가 필요하다. 서로 다른 말풍선이 동시에 해당되거나
   원문 획이 알려진 말풍선을 가로지르면 검토가 필요하다는 오류로 중단한다.
   같은 말풍선의 중복 검출은 겹침을 확인해 처리한다.
3. 확인된 내부 마스크에 여유를 두고, 새 글자 알파의 **모든 양수 픽셀**을 검사한다.
   외곽선·그림자·회전·곡선도 포함한다. 벗어나면 더 작은 크기나 안전한 내부 사각형을 시도한다.
4. 실패한 글자를 마스크로 잘라서 성공처럼 저장하지 않는다. 전체 문장이 안전하게 맞아야 저장한다.

기본 source 모드는 원래 편집 프레임 안에서만 배치한다. bubble 모드는 확인된 같은 말풍선 안에서
제한된 확장을 허용한다. 최소 글자 크기·strict·충돌 제약은 유지한다.
초록 사각형은 확인된 내부의 안전한 사각형이다.
식자 계획/적용 보고서의 `bubble_containment.status`로 검증 여부를 확인할 수 있다.

말풍선 마스크가 없거나 원문을 포함하지 않으면 `unavailable`이다.
표지/설명문 같은 비말풍선 글자는 원래 프레임에 배치하므로 이것을 말풍선 검증 성공으로 간주하지 않는다.
특정 영역은 `{"r1":{"require_bubble":true}}`로 확인된 말풍선이 없을 때도 중단하게 할 수 있다.
`respect_bubbles=false`는 기존 사각형 정책이며, 기존 그래프의 기본값은 그대로 유지한다.
모델의 마스크 자체가 잘못됐다면 실제 경계 보존을 보증할 수 없다.

## 여전한 580×203 반복 OCR

이번 로그에서도 같은 입력이 품질 검사에서 거절됐으며, **해결됐다고 판정하지 않았다**.
첨부 두 이미지는 표지 원본과 실행 화면이고, 설명 이미지의 실제 실패 크롭이 아니다.
v0.3.5 진단 JSON의 `layout_recovery`와 함께 같은 접두어의 `_source.png`, `_input.png`가 필요하다.
기존 파일이 null이면 복구 옵션/행 분할이 꺼진 경로인지부터 확인할 수 있다.

새 실패 로그와 JSON에는 실제 runtime 설정과 다음 복구 구분을 명시한다.

| strategy | 의미 |
| --- | --- |
| disabled_by_retry_option | retry_on_layout_failure=false |
| disabled_by_line_split | line_split=false |
| no_verified_alternative | 분할 근거가 되는 다른 간격을 찾지 못함 |
| ambiguous_rows_and_columns | 행/열 방향을 구분할 수 없음 |
| adapter_error_before_layout_recovery | 어댑터가 기존 생성 재시도 후 예외를 던짐 |
| verified_rows / verified_columns / shorter_horizontal_chunks | 대체 입력 계획을 찾음; 조각의 품질 검사는 별도 |

반복 검사를 끄거나 거절된 결과를 잘라 이어 붙이지 않는다.
실패 크롭을 확인하기 전에는 추가 토큰/patch 증가나 분할 휴리스틱을 해법으로 단정하지 않는다.

## 검증

260개 CPU 회귀 테스트를 통과했다. 실제 동봉 폰트로 뾰족한 말풍선의 사각형 이탈을 재현하고,
새 제약에서 글자 알파의 마스크 밖 픽셀이 0인지 검사한다. 원문 여백이 말풍선을 넘어선 경우,
옆 말풍선/겹친 마스크/중복 검출/마스크 없음/불가능한 배치도 검사한다.
검출·OCR 모델 응답은 대역이며, 사용자 실제 표지·580×203 크롭·만화 GPU 결과는 미검증이다.
