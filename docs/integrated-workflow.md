# 통합 워크플로: 검출부터 식자까지

현재 기본 진입점은 `lettering/example_workflows/08-integrated-tiled-cleanup-lettering.json`이다. 기존 01–07은 이전 작업의 호환·비교용으로 유지한다. 08은 한 번의 실행으로 다음 흐름을 연결한다.

`원본 → 전체/상세 검출 → 중복·문단 조각 정리 → 영역/줄별 OCR → ID별 번역 → 마스크 타일 계획 → 타일별 Qwen 제거 → 좌표 복원·검사 → 식자 → 저장`

## 기본 노드와 전용 처리의 경계

- 이미지 로드, 실제 타일 크롭, 크기 복원, 마스크 확대, 타일 내부 마스크 합성, 마스크 시각화, 미리보기, 최종 저장은 기본 노드를 사용한다.
- `MangaInpaintPlan`은 마스크 연결 요소를 소유 코어와 문맥으로 나눈다. `MangaInpaintAssemble`은 가변 개수 타일을 원본 좌표로 모으고 원문 잔존을 검사한다. 모델 로드·추론을 이 두 노드에 넣지 않았다.
- Qwen 인코더·샘플러·VAE는 기존 노드와 설치된 모델을 그대로 연결한다. 전체 원본 페이지가 Qwen 이미지 입력으로 직접 전달되지 않는다.

## 처리와 실패 정책

1. 검출의 auto는 큰 페이지에 native 1152px 창과 576px 상세 창을 함께 검사한다. 큰 페이지에서 예산을 넘으면 상세 창을 768px로 조정하거나 native 창만 유지한다. 실제 모델 응답에 따라 작은 글씨 복구 여부는 달라진다. 겹친 문단 조각은 포함 관계와 동일 행의 겹침으로 합치고, 서로 떨어진 행은 보존한다. 기본 상세 검출은 최대 64개 창으로 제한한다. 내부 타일 경계 3px 이내에 닿는 글자 검출은 별도 추적한다. 온전한 같은 종류의 검출이 해당 조각의 마스크 픽셀 98% 이상을 포함하면 조각 사각형을 제외하고, 부족하면 겹친 타일에서 같은 종류·유사한 행 높이의 조각을 연결한다. 수평/수직의 양쪽 바깥 끝이 각각 크롭 내부에서 관측된 경우만 온전한 영역으로 채택하며, segmentation은 조각 마스크의 합집합을 쓴다. 그래도 부족하면 잘린 방향과 반대쪽·직교 방향 문맥을 함께 넓혀 최대 3단계 재검출한다. 추가 재검출은 페이지당 최대 16회다. 한 조각의 재검출 실패만으로 즉시 중단하지 않고 다른 조각의 결과까지 모아 다시 판정한다. 최종적으로 온전한 검출 또는 양쪽 끝이 확인된 연결로 복구되지 않은 조각은 OCR 전에 오류로 중단한다. 정상적인 세로 글자는 모양만으로 제거하지 않는다. 분할 조각의 segmentation 픽셀은 삭제 마스크에 계속 보존한다.
2. OCR은 줄 분할 후 영역별로 재결합한다. 기본 tight crop은 끈다. 켜도 작은 문장부호·분리 획을 crop 경계에서 제거하지 않는다. 번역은 ID·개수 계약을 계속 검사한다.
3. 제거는 코하루처럼 최대 512px 소유 코어와 기본 128px 문맥으로 나눈다. 각 남은 마스크 픽셀은 타일 하나만 소유한다. 크롭과 복원 크기는 같은 좌표 출력을 공유한다. 타일 수는 추론 전에 제한한다.
4. 주변 색이 매우 균일하고 실제 대비 획이 있는 연결 요소는 보수적인 색 채우기를 먼저 시도한다. v0.3.2의 08은 text 영역의 주변과 내부가 단색을 지지할 때 검출 마스크가 놓친 획/잔점도 영역 안에서 보완한다. 검출 말풍선 다각형을 사용하는 기존 코하루와 완전히 동일한 판정은 아니다. 비교하려면 `uniform_fill=false`로 두면 된다. 남은 타일이 없으면 lazy 입력으로 Qwen 경로 전체를 실행하지 않는다.
5. 타일 합성 후에도 원문 대비 획이 거의 그대로이면 기본 `strict_cleanup=true`가 식자 전에 중단한다. 이것은 픽셀 변화 휴리스틱이며 완전한 OCR 재검증·정확한 배경 복원 판정은 아니다.
6. 실효 제거 마스크 밖 원본 픽셀은 정확히 유지한다. v0.3.2의 실효 마스크는 단색 text 영역에서 복구한 획을 포함할 수 있으며 Plan 출력으로 확인한다. text 영역 밖이나 단색으로 확인되지 않은 배경에서 완전히 빠진 글자를 자동으로 지웠다고 간주하지 않는다.
7. 식자는 외곽선·굵기·그림자 공간을 행 사이에도 확보하고, 가로 글자는 공통 기준선에 배치한다. 새 08의 reflow는 단일 줄바꿈을 풀어 가용 폭에서 먼저 배치한다. 폰트 자동 식별·원본 글자체 복제는 제공하지 않는다.

## 사용

저장소를 업데이트하고 ComfyUI를 재시작한 다음 08 JSON을 새로 불러온다. 원본 이미지, 검출/OCR 모델 번들, 기존 번역 서버를 선택하고 실행한다. 이전 07 캔버스를 그대로 사용하는 것만으로는 새 타일 경로가 생기지 않는다.

`제거 대상 마스크`는 보완 후의 실효 삭제 범위를 보여주고, `식자 직전 전체 배경`은 최종 식자 전 상태를 보여준다. OCR 원본/입력 조각과 식자 공간 미리보기도 제공한다. OCR JSON의 `region_resolution.boundary_recovery`에는 잘린 조각 수, 실제 재검출 횟수·크롭 좌표, 조각 연결 수, 복구된 검출 수와 크롭별 결과가 기록된다. 실패 시에는 `Manga boundary recovery` 로그에 같은 진단과 포함률이 남는다. OCR/번역 JSON과 최종 이미지는 기존 output/manga_translator 아래에 저장한다. 타일 계획·검사 보고서는 Plan/Assemble의 STRING 출력에 연결해 확인할 수 있다.

## 통합 모의 실행과 실제 실행의 구분

`python tools/simulate_integrated.py --destination <folder>`는 배포되는 08 API 그래프의 저장·미리보기 출력까지 실행한다. 실제 커스텀 노드, PyTorch CPU 텐서, OCR 줄 분할, ID별 JSON 검증, 타일 계획/복원, 폰트 식자와 파일 저장을 사용한다. 기본 이미지 노드는 CPU 등가 연산으로 실행한다. 프레임워크의 리스트 매핑과 unresolved lazy 링크 `(None,)`도 모의 실행에 포함한다.

RF-DETR·Hayai·번역 LLM·Qwen 응답은 합성 입력의 정답을 아는 대역이다. 소스는 재현 가능한 영어 테스트 글자이고 출력은 실제 한글 폰트다. 이 결과는 사용자가 올린 만화나 모델의 일본어 인식·GPU 제거 품질 실증이 아니다.

검증 시나리오는 전체 검출에서 일부러 빠진 본문의 상세 검출 복구, 영역/줄 대응, 단색 선처리+타일, 모든 영역의 타일 처리, Qwen 전체 생략, 원문을 그대로 반환하는 실패 중단이다. 576px 경계의 여러 줄 세로 조각·반쪽 문단을 넣은 성공 경로와, 문맥 재검출에서 빈 결과를 돌려 OCR·번역·Qwen·최종 저장 전에 중단하는 경로도 실행한다. 별도 회귀 검사로 타일 경계·빈 마스크·누락/크기 오류·실행량 제한·작은 문장부호 보존·생성 ZIP 설치 import를 확인한다. GPU 모델 실행 및 실제 ComfyUI 프런트엔드 가져오기/저장 검사는 별도 범위다.

## 참고한 기존 호출 경계

`ytoaa/koharu-remote`의 `ee6d9ddc82d9bfc4718383272f0e4797f805e2cd`에서 `patches/remote-models.patch`의 `inpaint_remote`와 `patches/remote.rs`의 `inpainting_tiled=true` 기본값을 확인했다. 코하루 내부의 scene/Rust 실행기를 가져오지 않고 ComfyUI 그래프로 이 처리 경계를 재구성했다.
