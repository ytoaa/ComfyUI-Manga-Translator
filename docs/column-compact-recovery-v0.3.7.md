# 다단 OCR / compact 경계 복구 — v0.3.7

## 실제로 확인된 입력

제공된 580×203 실패 PNG는 좌우 두 단의 가로 중국어 본문과 중앙 점선/번호 표시다.
전체 폭의 행 투영은 이 배치를 나누지 못했다. 제공된 진단에서 행 분할과 복구 옵션은 모두 켜져
있었고, 256/512 토큰에서 같은 반복 결과가 나왔다. 토큰 상한 증가로 해결된 사례가 아니다.

이 입력에 새 분할을 직접 적용하면 x=265에서 단이 나뉜다. 왼쪽은 9개, 오른쪽은 7개 입력이다.
중앙 번호 상자가 오른쪽 두 행에 걸쳐 있어 이 행들은 하나의 입력으로 유지한다.
117,740픽셀이 정확히 한 입력에 속하며, 조각을 좌표에 다시 놓은 배열은 원본과 완전히 동일하다.
첨부 이미지와 원문/로그는 저장소에 포함하지 않는다. 회귀 테스트는 별도로 그린 구조적 픽셀 입력이다.

## 동작

- 기존 두 patch 품질 시도도 실패했을 때 `line_split=true`, `retry_on_layout_failure=true`이면 적용한다.
  08의 기존 옵션으로 동작하며 새 노드는 없다. `auto`/`horizontal`만 가로 다단 후보를 검사한다.
- 충분히 넓은 단 사이 빈 열과 최소 세 개의 긴 가로 행/여러 구성요소를 가진 본문 두 단 이상을
  요구한다. 단의 픽셀 폭이 입력의 60% 미만이거나 불분명하면 다단으로 확정하지 않는다.
  이 규칙은 영상 기반 휴리스틱이며 모든 표/언어/스타일의 읽기 순서를 보장하지 않는다.
- 작은 종이 질감과 가는 스캔 경계는 분할 분석에서만 제외한다. 번호/보조 표시를 포함한 실제
  인식 이미지의 픽셀은 제거하지 않는다. 보조 여백은 다음 본문 단에 포함하며, 번호 상자를
  가르는 행 간격을 만들지 않는다. 왼쪽 단의 위→아래, 다음 단의 위→아래 순서로 읽는다.
- 복구 최대 16입력/영역 전체 최대 128작업, 자식 및 합친 결과 품질 검사를 유지한다.
  거부된 부모 문자열은 결과에 섞지 않는다. 진단에 `verified_multicolumn_rows`, 단 좌표/행 수와
  자식 입력 좌표가 남는다. 자식도 반복하면 해당 실제 입력을 저장하고 계속 중단한다.

800×1125 표지 로그의 조각 `[40.2787,339.4085,225,576]`은 세 번의 확장 창에서 복구되지 않았다.
기존 `[0,275,289,1125]`, `[0,211,353,1125]`, `[0,83,481,1125]` 이후,
이제 `[0,169,576,745]` compact 창을 한 번 더 검사할 수 있다. 좁고 긴 창의 다른 입력 모양을
시도하는 보완이며 새 창에서 모델이 완전한 제목을 찾는지는 아직 확인하지 않았다.

기존 조각 모두의 확장 복구를 먼저 끝내고 남은 조각에만 적용한다. 전체 복구 16호출/512검출 한도와
동일 label의 98% 지지 영역 포함 기준을 유지한다. 이미 실행한 full/detail/recovery 창은 재실행하지
않으며, 너무 큰 조각에는 compact 창을 억지로 만들지 않는다. `compact_context`가 로그에 남는다.
검출을 지우거나 낮은 점수의 조각을 무조건 통과시키는 처리는 없다.

## 업데이트와 남은 확인

`git pull` 후 ComfyUI를 재시작한다. v0.3.6 08을 쓰고 있다면 워크플로를 다시 가져올 필요는 없다.
OCR은 위 두 옵션을 유지한다. 토큰 수/반복 페널티/검출 임계값은 이 변경에서 조정하지 않는다.

CPU 픽셀 검사와 모델 응답 대역 회귀 검사는 실제 모델 정확도 검증과 다르다.
실제 Hayai가 분할된 중국어를 정확히 읽는지, 실제 RF-DETR가 compact 창의 표지 글자를
완전하게 검출하는지, 이후 번역/제거/식자 품질은 사용 환경의 재실행 확인 대상이다.
