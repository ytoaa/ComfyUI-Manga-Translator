# 실행과 프로젝트 관리

[목차](README.md) · [설정](configuration.md) · [문제 해결](troubleshooting.md)

## 설치와 업데이트

저장소는 `ComfyUI/custom_nodes/ComfyUI-Manga-Translator`에 둡니다. Git 설치는 해당 폴더에서 `git pull`하고 ComfyUI를 재시작한 뒤 브라우저를 새로고침합니다. ZIP 설치는 실행용 ZIP 하나를 풀고 폴더가 중복으로 중첩되지 않았는지 확인합니다. 개발용 source ZIP과 실행용 ZIP을 두 노드 팩으로 중복 설치하지 않습니다.

[통합 08](../lettering/example_workflows/08-integrated-tiled-cleanup-lettering.json)의 일반 JSON을 가져옵니다. `.api.json`은 같은 처리 그래프의 API 표현이며 다른 워크플로우가 아닙니다. 모델·서버 설정은 [설정 문서](configuration.md)를 따릅니다. 이전에 저장한 URL·모델 ID·폰트를 새 예제의 초기값으로 덮어쓰지 않았는지 확인합니다.

## 한 장과 폴더

| 입력 | 첫 입력 노드 | 실행 |
| --- | --- | --- |
| 한 장 | `input_mode=이미지 한 장`, 이미지 선택/업로드 | Run |
| PC 폴더 | `PC 폴더 업로드`, 업로드 완료 후 `project_name` 확인 | `시작·재개`, Run |
| 서버 폴더 | `input_mode=폴더 프로젝트`, `input_folder`에 ComfyUI/input 아래 상대 경로 | `project_name`, `시작·재개`, Run |

PC 폴더는 하위 상대 경로를 보존해 ComfyUI에 업로드합니다. 모든 파일의 업로드가 끝나야 폴더 입력이 반영됩니다. 로컬 PC의 절대 경로를 서버 폴더 경로로 넣지 않습니다.

폴더는 숫자 순서로 한 페이지씩 현재 캔버스에서 실행합니다. 첫 Run이 첫 페이지를 처리하며, 첫 노드에서 페이지·진행 상태를 봅니다. 다음 페이지 자동 실행에는 브라우저를 열어 둡니다. 사이드바나 별도 백그라운드 추론 작업자를 실행하지 않습니다.

## 제어 동작

| action | 대상과 동작 |
| --- | --- |
| `시작·재개` | 아직 처리하지 않았거나 입력이 바뀐 페이지를 진행합니다. 기존 failed/needs_review를 일괄 재시도하지 않습니다. |
| `실패 재시도` | failed 페이지를 새 시도로 처리합니다. needs_review는 유지합니다. |
| `실패·검수 재시도` | failed와 needs_review를 새 시도로 처리합니다. completed/unchanged_blank는 유지합니다. |
| `상태 확인` | 저장된 프로젝트와 현재 실행 결과를 확인합니다. 다음 페이지를 시작하지 않습니다. |
| `일시정지` | 현재 페이지가 끝난 뒤 연속 처리를 멈춥니다. |

노드의 `연속 처리 중지 · 현재 페이지 이후` 버튼도 페이지 사이에서 멈춥니다. 기본 ComfyUI 중지는 현재 실행 자체를 중단합니다. 브라우저를 닫아도 이미 실행 중인 페이지는 끝날 수 있습니다. 재개할 때 현재 큐·이력을 먼저 대조합니다.

새 시도는 이전 `attempt-*`를 덮어쓰지 않습니다. 검수 페이지를 재시도해 다시 검수가 되어도 한 실행에서 무한 재시도하지 않습니다. 성공을 숨기거나 failed를 completed로 강제 변경하는 초기화 스크립트는 사용하지 않습니다.

## 같은 프로젝트와 설정 변경

새 08의 단계 재사용 노드를 사용하는 프로젝트는 모델·번역·식자 설정을 바꿔도 이전 시도를 보존하며 새 시도를 만들 수 있습니다. `시작·재개`는 바뀐 설정의 페이지를 선택하고 각 checkpoint가 영향받지 않은 결과를 재사용합니다. 저장된 설정 revision을 남깁니다. 이전 작업이 실행/준비 중이면 먼저 그 작업을 정리해야 하며 실행 신원을 바꿔 덮어쓰지 않습니다. 서버·정규화·스캔 범위 변경과 단계 재사용이 없는 구형 그래프는 기존 보호 검사를 유지합니다.

0.7.2부터 자동 연속 실행은 시작 시점의 처리 설정과 검수 내용을 유지합니다. 도중에 변경하면 해당 자동 요청만 거부하고 기존 기록·완료 티켓은 보존합니다. `연속 처리 중지 · 현재 페이지 이후`로 멈추고 현재 페이지 결과가 수집된 뒤, 바꾼 설정으로 수동 `시작·재개`하세요. 새 run은 별도의 그래프 기록을 남깁니다.

원문/번역 검수 노드의 편집 내용은 워크플로우와 함께 저장하세요. 폴더에서 이미 끝난 페이지를 수정한 뒤 `시작·재개`하면 설정 변경으로 새 시도가 선택됩니다. 이전 결과와 `attempt-*`는 보존됩니다. 같은 설정으로 단순 재개하면 완료 페이지를 다시 처리하지 않습니다.

## 저장과 상태

한 장의 기본 저장 위치:

```text
ComfyUI/output/manga_translator/integrated_tiles_*.png
ComfyUI/output/manga_translator/ocr_*.json
ComfyUI/output/manga_translator/translation_*.json
```

폴더 기록은 `ComfyUI/output/manga_translator/workflow_projects/<project_name>/` 아래입니다. 페이지별 `attempt-*/state.json`, 원본 정규화 이미지·JSON·결과 PNG, 요약과 export 기록이 남습니다. 결과 보고서의 상대 경로를 기준으로 찾습니다.

| 상태 | 의미 |
| --- | --- |
| completed | 처리가 끝나 결과가 수집됨. OCR/번역의 의미 정확도 보증은 아닙니다. |
| needs_review | 원본 보존·미검출·제외 효과음·미확정 영역 등 검수가 필요함 |
| unchanged_blank | 균일 RGB 픽셀 등 제한된 빈 페이지 조건을 확인해 원본 저장 |
| failed | 단계 오류로 최종 결과를 확정하지 못함 |
| paused | 실행 신원·큐·자원 등의 문제로 추가 제출 중지 |

영역이 0개인 일반 이미지가 곧 빈 페이지는 아닙니다. 선택 영역이 없으면 OCR·번역·Qwen·식자를 건너뛰고 원본을 남기며 검출 실패 가능성을 검수합니다.
