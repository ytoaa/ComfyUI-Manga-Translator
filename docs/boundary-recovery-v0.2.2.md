# v0.2.2 — 실제 실패 좌표를 사용한 복구 경로 보완

기준: main `3658ef1785f8826a50622682064f05e033b12ee9` (v0.2.1).

사용자 로그의 확정 사실은 `bbox=[465.2586364746094,277.3353576660156,576.0,346.1344299316406]`,
`edges=['right']` 조각이 복구되지 않아 OCR 전에 중단됐다는 것이다. 이 로그에는 재검출의
크롭과 원시 결과가 없어, 검출 누락·계속 잘린 박스·98% 포함 기준 미달 중 실제 원인을
확정할 수 없다. 사용자 이미지의 GPU 모델 응답은 이번 검증에 포함하지 않았다.

## 코드에서 확인한 부족한 경로

- v0.2.1은 새롭고 온전한 박스만 복구 증거로 썼다. 서로 보완되는 잘린 박스는 모으지 않았다.
- 잘린 방향만 확대하고 반대쪽·직교 방향 여백은 고정했다. 페이지 끝에 닿은 뒤
  서로 다른 단계가 같은 크롭이 되어 중복 생략되기도 했다.
- 첫 조각이 실패하면 즉시 중단해 나중 조각의 재검출 결과를 활용하지 못했다.
- 예외에는 재검출 크롭·응답 좌표·포함률이 없었다.

## 변경

같은 종류의 조각끼리 실제로 겹치고 행/열 두께가 비슷할 때 연결한다.
전체 그룹의 두께 비율 0.65 이상, 교차 축 겹침 80% 이상,
진행 축 겹침 3px 및 작은 조각의 10% 이상을 요구한다.
서로 다른 크롭 창에서 관측한 조각이어야 하며, 양쪽 바깥 끝이 각각 크롭 내부에서
보였다는 증거가 있을 때만 온전한 영역으로 채택한다. 이 판정은 의미론적 문단 검증을
대체하지 않는 기하 휴리스틱이다. 끝점이 없거나 떨어진 조각은 임의로 연장하지 않는다.
여러 행을 가로지르는 세로 조각이 두께가 다른 수평 본문을 연결하지 못하게 제한한다.
수직 글자도 같은 방식으로 양 끝 증거를 확인한다.

새 재검출에서 얻은 부분 박스도 연결 후보에 포함한다. 연결 영역의 마스크는 각 조각의
실제 segmentation 픽셀 합집합으로 만든다. 소유하지 않은 배경을 사각형으로 채우지 않는다.
문맥 여백은 모든 방향으로 단계별 확대하고, 모든 복구 결과를 모은 뒤 미해결을 판정한다.
기존 98% 지원 기준, 추가 검출 16회 및 결과 상한은 유지한다.

성공 JSON의 `region_resolution.boundary_recovery`에 `stitched_regions`, `attempts`를 추가했다.
실패하면 `Manga boundary recovery` 로그가 크롭별 bbox·잘린 방향·완전/부분 결과 수·포함률을
남긴다. 오류 메시지에도 포함률과 실행 크롭이 남는다. 노드 타입·08 그래프 연결은 유지했다.

## 재현과 검증

전달된 좌표에 보완 조각 `[512,278,1088,346]`, `[1024,278,1486,346]`을 합성해 넣고,
넓은 재검출은 빈 응답을 주었다. 이 보완 조각은 테스트 데이터이며 실제 사용자 모델 응답이 아니다.
같은 입력에서 v0.2.1은 재검출 2회 후 제공된 로그와 같은 예외로 중단됐고,
v0.2.2는 추가 추론 없이 양 끝이 관측된 약 465..1486px의 본문으로 복원했다.
[비교 결과](logged-fragment-repro-v0.2.2.json).

전체 Python 회귀: **157 passed** (이전 144개 + 추가 13개).
추가 검사는 실제 로그 좌표, 수평/수직 연결, 끝점 누락, 떨어진 조각, 동일 창 중복,
세로 오조각 제외, segmentation 합집합, 크롭 다양화, 진단 로그,
뒤늦게 복구된 결과의 재사용, 새 부분 검출 연결과 08 전체 경로를 다룬다.
