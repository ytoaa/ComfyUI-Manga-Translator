# v0.3.3 — 다단 가로 본문 OCR 방향과 토큰 한도

보고된 확정 사실은 `crop=278x446`, `tokens=256/256`, `characters=304`,
`patch_budget=256`에서 `ocr_token_limit`로 중단됐다는 것이다.
이는 어댑터가 읽은 비종료 토큰 수가 출력 한도에 도달했다는 뜻이다.
304자가 실제 본문인지, 오인식/반복인지, 어느 페이지 좌표의 크롭인지는 해당 로그만으로 확정하지 않는다.
잘린 결과를 성공한 원문으로 반환하지 않는 검사는 유지한다.

## 코드 원인과 변경

기존 행 분할은 `height >= width*1.25`이면 먼저 세로쓰기 방향으로 고정했다.
가로 문장이 여러 줄 들어간 세로로 긴 사각형도 세로쓰기로 취급해,
실제 가로 행이 보이는데도 분할되지 않고 큰 크롭 전체가 OCR에 들어갈 수 있었다.
큰 문단은 출력 한도와 시각 patch 예산도 여러 행이 공유한다.

auto에서는 가로/세로 픽셀 투영을 모두 검사하고, 실제 행/열 모양과 분리 간격으로 판단한다.
선택하려는 방향으로 긴 밴드가 75% 이상 있어야 하므로 가로 한 줄의 개별 글자를
세로 열로 뒤집어 읽는 것도 줄인다. 방향이 애매하면 기존 입력을 유지한다.
이는 의미론적인 지면 분석이나 완전한 다단 읽기 순서 복원은 아니다.

첨부된 1060×1500 지면에서 `(150,900,428,1346)`, `(150,550,428,996)`,
`(480,150,758,596)`의 **분석용** 278×446 크롭을 비교했다.
기존 함수는 각각 한 덩어리로 유지했고 수정 후에는 가로 20/16/17행으로 분할했다.
실제 실패했던 detector ROI를 제공받은 것은 아니므로 동일 크롭의 오류 재현이라고 주장하지 않는다.
이 검사는 픽셀 분할만 실행했으며 Hayai 모델 추론은 실행하지 않았다. 원본 이미지는 저장소에 포함하지 않는다.

## 설정

업데이트 후 ComfyUI를 재시작하고 새 08 JSON을 가져온다.
OCR 노드에는 다음 선택 입력을 추가했다.

- `text_direction=auto`: 픽셀에 근거한 행/열 판단. 이 공략집처럼 가로 본문이면 horizontal로 명시할 수 있다.
- `horizontal`: 가로 행 분할, 위에서 아래로 읽기.
- `vertical_rtl` / `vertical_ltr`: 세로 열 분할 후 오른쪽/왼쪽 열부터 읽기.
- `retry_on_token_limit=true`: 토큰 한도 실패 시 같은 입력의 한도를 2배로 한 번 증가. 상한 2048.

새 08은 auto와 토큰 재시도를 켠다. 기존 저장 그래프/07의 토큰 재시도 기본은 false로 유지한다.
OCR의 text_direction은 식자 계획의 direction과 별개다.
`line_split=false`면 수동 방향을 골라도 행 분할은 실행하지 않는다.
기존 그래프에서 임시로 max_new_tokens를 512로 올릴 수 있지만, 방향/크롭 문제의 해결을 대신하지 않는다.

## 재시도와 진단

기본 한도 256이면 재시도는 512다. 이미 1536이면 2048, 2048이면 더 늘리지 않는다.
한도를 늘린 뒤에도 실패하면 중단하며 첫 시도의 잘린 문자열과 이어 붙이지 않는다.
반복 재시도도 최대 한 번이고, 둘이 함께 발생해도 한 patch 설정에서 생성은 최대 세 번이다.
후단의 quality_guard가 다른 patch 설정으로 한 번 재검증하는 기존 경로는 별도로 유지한다.
출력 한도/반복 보정 이외의 generation 옵션은 복사해 보존한다.

영역별 `ocr_diagnostics`에는 설정한 방향과 토큰 재시도 설정을 저장한다.
각 patch 시도의 `generation_attempts`에는 실제 max_new_tokens, repetition_penalty와
accepted/ocr_token_limit/ocr_repetition_loop 상태를 기록한다.
완료되지 않으면 성공 JSON을 생성하지 않고 오류 로그로 남긴다.

## 검증 범위

합성 픽셀로 세로로 긴 가로 20행, 가로 한 줄의 글자 열 오판 방지,
실제 세로 열의 양방향 순서, 토큰 한도 증가/상한/끄기/재실패와 반복의 결합 한도를 검사한다.
배포 08 전체 그래프에서도 재시도 실패가 번역·Qwen·최종 저장에 도달하지 않는지 검사한다.
기존 워크플로 설정 직렬화와 전체 CPU 회귀·그래프 모의 실행·패키지 검사도 실행한다.
사용자 GPU의 실제 검출 ROI, Hayai 중국어 인식 정확도와 전체 지면 식자 품질은 재실행 확인 대상이다.
