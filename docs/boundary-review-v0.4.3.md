# v0.4.3: 미복구 경계의 원본 보존과 검수

## 실제 진단에서 확인한 것

v0.4.2의 실제 폴더 재실행은 completed 10 / needs_review 2 / unchanged_blank 2 / failed 4였다. 폰트 06/17, 겹친 말풍선 12, 경계 복구 14가 통과했고 04/08/09/11은 검출 경계에서 중단됐다. 제공된 네 JSON의 page bbox를 context_window만큼 옮겨 주변 PNG와 대조했다.

| 페이지 | coverage | 문제 좌표의 주변 이미지 |
|---|---:|---|
| 04 | 0% | 턱 아래·목 주변 그림 선 |
| 08 | 0% | 큰 효과음의 일부가 text로 분류됨 |
| 09 | 83.1% | 귀 안쪽의 그림 선 |
| 11 | 0% | 얼굴의 코·볼 주변 선 |

이 네 사례는 모든 미복구 경계를 필수 대사로 취급하면 페이지 전체를 계속 실패시키는 문제를 보여준다. 다른 페이지의 미복구 조각이 모두 오검출이라는 뜻은 아니다. 모델 점수나 새 창에서의 미검출만으로 글자 없음·복구 성공을 판정하지 않는다. threshold, 98% support 기준과 복구 예산은 유지한다.

## 통합 08의 정책

검출 노드의 새 선택값 `boundary_policy`는 `preserve_review`(기본)와 `strict`다. 함수 단위 검출 API의 기본 strict는 유지하며, 캔버스 노드·통합 08은 preserve_review를 사용한다.

- 기존 재검출과 조각 연결을 먼저 실행한다.
- 미복구 조각의 전체 bbox와 16px 여유를 보존한다. 그 보존 영역에 닿는 완전 검출 문단도 전체 bbox+16px를 보존한다. 접촉이 이어지는 문단도 같은 방식으로 제외한다. 부분적으로 지워진 문단을 만들지 않는다.
- 해당 검출과 마스크 조각을 OCR·번역·제거 대상에서 제외한다. 나머지 영역의 정상 처리는 계속한다. 다른 모델 오류, 잘못된 응답, 메모리·영역 한도, OCR/식자 오류는 그대로 실패한다.
- 원문/번역 JSON에 `needs_review`, `boundary_review`, 사유 `unresolved_detection_boundary`를 기록한다. 원본 보존은 번역 완료나 무문자 확인을 뜻하지 않는다. 실제 글자라면 그 부분의 번역은 빠진다.
- 마스크 합성에서 보존 사각형을 제외한다. GrowMask와 단색 잉크 보완 뒤에도 제외를 적용하며, 식자 계획은 해당 부분의 원본 픽셀을 복원한다. 모든 새 글자 alpha가 보존 영역을 침범하지 않아야 한다. 배치 검수 미리보기의 빨간 사각형이 보존 영역이다.
- 폴더 결과 수집은 원문/번역의 보존 명세가 같고 최종 PNG의 보존 영역이 정규화 입력 PNG와 픽셀 단위로 같음을 검사한다. 다르면 결과를 완료로 수집하지 않는다. 나머지 글자까지 처리돼도 페이지 상태는 needs_review다. 검수 결과는 기존 자동 완료 내보내기에 포함하지 않는다.
- OCR 편집 여백이나 영역 병합이 보존 영역에 걸리면 명시적으로 중단한다. 보호 구역을 줄이거나 통과 처리하지 않는다.

strict를 고르면 종전처럼 미복구 경계 하나도 페이지 오류로 남긴다. 사용자 정의 그래프에서 preserve_review를 사용하려면 같은 검출 결과를 영역 정리·실제 글자 마스크·식자 계획에 연결하고, 영역 JSON을 타일 제거 계획에 연결한다. 제공 통합 08은 이미 이 연결을 갖추고 있다.

## 적용

`git pull` 후 ComfyUI 재시작·브라우저 새로고침, 같은 프로젝트의 `실패 재시도`를 실행한다. 기존 v0.4.x 통합 08에서도 새 선택값 생략 시 기본 preserve_review가 적용된다. 새 08에는 선택값과 설명이 표시된다. 생략과 기본값의 fingerprint를 동일하게 정규화하므로 기존 프로젝트를 재사용한다. strict는 다른 처리 설정이다.

이번 보고서 기준으로 실패 4페이지만 새 시도를 만들고, 완료 10·검수 2·균일색 원본 유지 2의 기존 기록은 보존한다. 이전 시도·실패 진단도 보존한다. needs_review로 처리된 페이지는 결과 PNG와 원문/번역 JSON의 보호 좌표를 보고 수동 검수한다. 같은 실패 재시도는 이미 검수 상태인 페이지를 자동 반복하지 않는다.

## 검증 경계

첨부 PNG는 실제 시각 진단에 사용했다. 회귀 검사는 네 좌표에서의 검출 응답 대역, 연결 문단 제외, 잘못된 보호 좌표 거부, 확대 마스크·단색 보완·실제 폰트 식자에서의 원본 픽셀 보호, 프로젝트 fingerprint 호환과 결과 수집 검사를 포함한다. 실제 네 페이지의 RF-DETR/Hayai/Qwen GPU 재추론 결과는 아니다. 새 needs_review 결과의 문장 정확도와 실제 제외 범위는 DGX 실행 후 검수해야 한다.
