# 마스크 기반 회전 OCR·제거 경계 v0.6.0

## 실제 입력에서 확인한 원인

사용자가 올린 세 중간 이미지 중 060258에는 한국어를 쓰기 전부터 밝고 울퉁불퉁한 띠가 있다. 따라서 이 얼룩은 새 글자 외곽선만의 문제가 아니라 제거/배경 복원 단계에서 이미 발생했다. 이미지 파일만으로 단색 채우기와 Qwen 생성 중 어느 경로가 만들었는지는 확정하지 않는다.

새 detection_audit의 제외 좌표 140,1295–321,1355 및 387,1239–575,1304 등은 카드의 Skill1 설명과 Skill2 설명 위치에 해당한다. 효과음 분류가 일부 일반 글자에도 적용된 것은 확인된다. 31회는 여전히 중복 추론 관측 수이며 31개의 고유 문장이 아니다. Skill3 등 모든 누락 글자의 원인이 이것뿐이라고 단정하지 않는다. r1의 MY PROFILE 오독과 반복은 OCR source에 이미 존재한다.

## OCR 입력의 회전 보정

새 통합 08의 MangaRegionCrops에는 auto_deskew=true와 text_pixel_mask가 연결된다. 기존 기본 함수/API에서 생략한 값은 false다. 보정은 다음 계약을 따른다.

- 검출 마스크 안의 로컬 명암 성분으로만 각도를 탐색한다. 원문 문자열을 추측해 각도를 정하거나 품질 검사를 끄지 않는다.
- 4 Mi-pixel 이하 가로 프레임을 긴 변 768px 이하로 분석한다. 성분 수·각도 탐색·행 수·회전 후 크기에 상한이 있다. 2.5° 이상 25° 미만 회전과 투영 집중도 증가, 여러 행과 분석 잉크 범위가 확인될 때만 계획을 만든다. 확인되지 않으면 기존 OCR 경로를 유지하고 이유를 ocr_geometry_analysis에 기록한다.
- 보정은 OCR용 RGB 복사본에만 적용한다. 원본 페이지와 crop/edit 좌표, 제거 마스크의 좌표는 변경하지 않는다. 패딩 색은 크롭 가장자리의 관측 중앙값이다.
- ocr_region_plan에는 source_size, correction_degrees, source_angle, rectified_size, rows, coordinate_frame=rectified_crop_pixels를 명시한다. 행은 보정된 입력 전체를 겹침 없이 분할한다. 보정 프레임을 원본 좌표인 것처럼 보고하지 않는다.
- MangaOCRAdaptive는 같은 계획을 검증한 후 행별로 읽고 진단·입력 이미지를 출력한다. MangaCollectOCR는 manifest의 계획과 실제 OCR 보고서가 일치하는지 검사한다. 작은 글씨 patch 배정, 반복·토큰·누락 검사와 실패 중단 정책은 유지한다.
- 기존 다단 페이지의 verified_page_rows 계획이 있으면 우선 사용한다. 수직 프레임은 자동 보정하지 않는다. 수동 OCR 방향을 세로로 강제할 때는 auto_deskew를 끈다.

첨부된 612×221px 크롭의 기하 분석에서 약 13°의 기울기를 확인했다. 변경 픽셀에서 만든 시험용 지지 범위로는 -13.5°와 네 입력 조각이 나왔다. 이는 실제 RF-DETR 원문 마스크를 다시 추론한 결과가 아니며, 실제 Hayai 인식 정확도가 개선되었다는 증거로 부르지 않는다. 실제 새 실행의 ocr_region_plan과 행/조각 이미지를 확인해야 한다.

## 식자 기하 연계

MangaLetterPrepare는 확인된 원문 각도를 source_orientation에 전달한다. 하이브리드 식자 계획은 원본/제거 배경/스타일 참조 마스크를 같은 각도로 정렬한 복사본에서 글자 크기·행 수·정렬을 측정한다. 기울어진 여러 줄의 전체 높이가 한 글자 높이처럼 측정되는 문제를 줄인다. 실제 말풍선 검사와 배치는 계속 원본 좌표를 사용한다.

가로 식자의 기본 회전에는 원문 각도를 사용하고, 명시한 영역별 rotation은 우선한다. 가로/세로 통일 설정은 계속 읽기 방향을 정하며, 세로 통일에 원문의 가로 기준 각도를 자동 적용하지 않는다. 선택한 폰트로 렌더링하는 방식이며 원본 폰트나 장식 스타일을 복제하는 기능은 아니다.

## 제거 마스크 경계

MangaInpaintAssemble의 blend_width는 0~32px이며 새 08은 8px이다. 생략/0은 기존 이진 합성이다. 단색 채우기와 생성 타일의 합성이 끝난 뒤, 전체 페이지의 허용된 제거 마스크 기준으로 여유 부분만 원본 배경과 점진적으로 합성한다.

검출/보완된 원문 마스크 픽셀의 알파는 항상 1이다. 지운 글자가 블렌딩 때문에 되살아나지 않도록 원문 영역의 제거 강도를 낮추지 않는다. 마스크 밖과 보호 영역은 그대로 유지한다. 타일의 소유 경계가 아니라 전체 제거 마스크를 사용하므로 내부 타일 접합선이 새로운 fade가 되지 않는다. EDT는 문맥을 포함한 512px 코어별 제한된 메모리로 계산한다. edge_blend 보고서에 폭·여유 픽셀 수·원문 비감쇠를 남긴다.

이 처리는 경계의 급격한 변화를 완화한다. 이미 잘못 생성된 색이나 사라진 배경 무늬를 원래대로 재구성하지 않는다. 마스크가 놓친 글자의 복구도 보장하지 않는다. 식자 직전 전체 배경을 계속 검수한다.

## 적용 및 남은 한계

코드를 업데이트하고 ComfyUI를 재시작한 뒤 새 통합 08을 가져온다. 하단 디버그의 OCR 보고서에서 region_plan과 region_coordinate_frame, 식자 계획에서 transform과 source_profile, 제거 결과에서 edge_blend를 확인한다.

이번에는 처리 입력과 설정이 바뀐다. v0.5.2 프로젝트와 같은 이름으로 새 설정을 덮어쓰지 않으며 폴더 프로젝트는 새 project_name으로 실행한다. 원본 input_folder는 유지한다. 기존 시도·결과는 남는다. 이전 캔버스를 그대로 쓰면 auto_deskew 생략=false, blend_width 생략=0으로 기존 동작이 유지된다.

하단 스킬 글자는 모델이 onomatopoeia로 분류한 상태다. 이 릴리스는 이를 자동 승격하지 않는다. 해당 분류의 글자도 처리하려면 기존 공통 ‘효과음·표지 큰 글자 포함’을 켜야 하며, 장식 글자와 그림 선 오검출도 포함될 수 있다. 단순 점수나 작은 박스라는 이유로 모든 제외 후보를 자동 편집 대상으로 바꾸지 않는다.

r1은 여전히 하나의 논리 영역이다. OCR 행 분리는 카드 항목을 독립 번역/편집 영역으로 재구성하는 것과 다르다. 카드의 항목별 레이아웃 복원과 완전한 누락 검출, 번역 의미 정확도는 남은 과제다. 실제 DGX에서 새 08의 해당 이미지 Hayai/Qwen 재추론은 수행하지 않았으며 CPU의 기하·마스크·모의 호출 검증과 구분한다.
