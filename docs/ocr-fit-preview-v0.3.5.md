# 반복 OCR 복구·식자 최소 크기·JSON 미리보기 (v0.3.5)

업데이트: `git pull` → ComfyUI 재시작 → **새 08 GUI JSON을 다시 불러오기**.
기존 저장 그래프에는 새 복구/식자 옵션이 자동 적용되지 않는다.

## OCR/번역 저장 결과를 바로 보기

08의 OCR JSON 저장과 번역 JSON 저장 출력에 각각 기본 `PreviewAny`를 연결했다.
새 커스텀 미리보기 노드는 필요 없다. 캔버스에는 `미리보기 아무거나` 또는
ComfyUI 언어/버전에 따라 `Preview as Text`로 보인다.
저장되는 값과 번역에 전달하는 값은 그대로 유지한다.
OCR이 실패한 실행에서는 저장 JSON 자체가 만들어지지 않으므로 아래 실패 입력을 확인한다.

## 512로 올렸는데도 반복이 남는 이유

첨부 로그는 `max_new_tokens=512`에서도 두 patch 설정(256/512) 모두
`short_repetition`에 걸린 경우다. 토큰 길이 제한과 별개의 오류다.
patch 변경은 같은 이미지를 다른 NaFlex 크기로 넣는 것이므로 입력 배치가 나쁘면 해결되지 않을 수 있다.
해당 580×203 실제 OCR 크롭은 첨부되지 않았으므로 정확한 원인은 아직 확정하지 않는다.
제공된 워크플로는 auto 방향/행 분할/품질 검사 사용을 확인했다.

새 08의 `retry_on_layout_failure=true`는 기존 patch 재시도도 품질 검사를 통과하지 못하면
확인 가능한 다른 행/열 분할 또는 더 짧은 가로 조각을 한 번 시도한다.

- 분할 판단에서만 좁고 거의 연속적인 테두리 획을 제외하고, 뚜렷한 행/열 사이 빈 간격을 찾는다.
  약한 글씨는 대비 8까지 검사한다. 실제 OCR 크롭에서는 테두리나 원문 픽셀을 삭제하지 않는다.
- 여러 획/글자가 있는 길쭉한 띠가 확인돼야 한다. 하나의 큰 연결 글리프를 여러 행으로 분해하지 않는다.
  방향이 애매하거나 안전한 간격이 없으면 임의 좌표에서 자르지 않는다.
- 최대 16개 대체 조각, 영역당 기존 입력과 복구 입력 합계 최대 128개다. 재귀 재분할은 하지 않는다.
  `line_split=false`면 이 재분할도 하지 않는다. 토큰/반복 생성 재시도 상한은 유지한다.
- 모든 조각과 합친 텍스트가 기존 품질 검사를 통과해야 한다.
  실패한 큰 입력의 글자를 일부 섞거나 반복 부분만 지우지 않는다.
- JSON에 부모 입력의 거절 사유·patch/생성 재시도와 대체 조각의 좌표/크기/검사 결과를 기록한다.
  OCR 입력 미리보기는 성공적으로 채택된 조각을 보여준다.

실패가 지속되면 다음 경로에 UUID로 구분한 진단을 남긴 뒤 중단한다.

```text
ComfyUI/output/manga_translator/ocr_failures/
  ocr_<id>_source.png   # 해당 OCR 영역 원본
  ocr_<id>_input.png    # 실제 실패한 입력 조각
  ocr_<id>.json        # 사유/크기/좌표/재시도/거절된 텍스트(가능한 경우)
```

실제 사용자 환경의 출력 폴더 설정을 따른다. 진단 저장 실패가 원래 OCR 예외를 가리지 않는다.
어댑터가 토큰 한도/반복 예외를 직접 던진 경우에도 입력/생성 시도 진단을 남긴다.
어댑터 예외의 기존 재시도와 중단 정책은 유지하며, 이 분할 복구는 품질 검사 거절 후에만 적용한다.
실패 입력이 정상 문자 하나라면 모델 오인식이나 반복 검사 오탐도 검토해야 한다.

## `no safe lettering fit above 60px`

기존 최소 크기는 `max(min_font, ceil(원문 크기 × min_scale))`이다.
예를 들어 원문 크기 추정이 109px이고 `min_scale=.55`면 최소가 60px이 된다.
한 글자 원문보다 번역이 길거나 원문 크기 추정이 크면, 영역에 남는 공간이 있어도 이 제한에 걸릴 수 있다.
스크린샷만으로 실제 r1의 원문/번역/정확한 bbox와 방향은 확정하지 않는다.

새 08은 `MangaLetterPlan.fit_policy=readable`을 사용한다.
우선 기존 원문 비율 제한과 사용 가능한 배치를 모두 시도하고,
맞지 않을 때만 같은 허용 영역에서 **설정된 절대 `min_font`(기본 10px)**까지 더 줄인다.
이 경우 보고서에 `source_ratio_relaxed=true`, 적용 크기와 최소 크기를 표시한다.

- 원문 크기 상한, 프레임/실제 말풍선 경계, 충돌 검사, 원문 밖 그림 보존은 유지한다.
- `strict`, `source_ratio`, 영역별 명시적 `min_scale`은 비율 제한을 유지한다.
- 명시한 `min_font`, `max_lines`, 방향과 줄바꿈 설정을 무시하지 않는다.
- 그래도 맞지 않으면 전체 저장 전에 중단한다. 오류에 원문 상한/최소 크기/방향/프레임을 표시한다.
- 방향이 잘못 추정된 경우에는 영역별 direction을 지정해야 한다. 추가 축소는 방향/원문 크기 추정의 정확성을 보증하지 않는다.

ComfyUI의 저장 노드가 오류로 실행되지 않으면 화면에는 이전 실행의 이미지가 남아 있을 수 있다.
미리보기만으로 이번 실행의 저장 성공을 판정하지 않는다.

## 검증 범위

합성 픽셀 입력·실제 동봉 폰트·CPU 텐서와 모델 응답 대역으로 검사했다.
프레임이 있는 580×203 문단을 네 행으로 복구할 때 모든 원문 픽셀 보존,
하위 입력 실패/합친 반복의 중단, 재분할 상한, 실패 PNG/JSON 저장을 검사한다.
한 글자 원문보다 긴 번역이 기존 비율 최소 아래에서 같은 프레임에 맞는 경우와
strict/명시적 제한 유지도 검사한다. 기본 미리보기 두 개는 저장 노드 출력에 직접 연결한다.
사용자 실제 OCR 크롭·번역 JSON 및 GPU 실행은 아직 재현/검증하지 않았다.
