# OCR 전 다단 본문 정리 — v0.3.11

이번에 받은 OCR 저장 JSON으로 문제 발생 단계를 확인했다. 큰 영역 하나가 가운데 단과
오른쪽 단을 함께 읽고, 다른 영역이 같은 오른쪽 단을 다시 읽었다. 또 다른 큰 영역은
가운데·오른쪽 본문에 겹쳤다. 여러 단을 가로지른 가로 행도 있었다. OCR 내부에서 입력을
행·열로 나눠 읽더라도 결과를 큰 영역 하나로 다시 합치므로 번역 중복과 식자 충돌이 남았다.
엉뚱한 고유명사와 문장도 번역 전 source에 이미 있었다. 반복·누락 휴리스틱 통과는 정확한
인식의 증거가 아니다. 토큰 한도나 글자 축소만으로 해결할 문제가 아니었다.

## 동작

새 08의 기존 MangaRegionCrops에 refine_page_columns=True를 설정한다. 반복된 좁은 검출에서
3~8개의 단 후보를 찾고, 단을 가로지른 영역이 최소 2개이며 실제 빈 열과 가로 본문 행이
단 구분을 뒷받침할 때만 정리한다. 좌표·페이지 크기·문자열을 특정 입력에 하드코딩하지 않는다.
수동 영역, 단 근거 부족, 여백 모호함은 기존 영역을 유지한다.

겹친 검출은 단 안에서 한 번만 소유하고, 문단 간격과 확인된 행을 이용해 최대 8개 행 묶음으로
논리 영역을 만든다. 긴 문단의 마지막 한 행만 작은 프레임에 남지 않도록 묶음을 균등 분배한다.
단 사이 밝은 번호도 여백 검사에 반영하며, 보조 번호가 두 행에 걸치면 함께 읽어 자르지 않는다.
종이 잔점·가는 선을 무시하는 것은 분할 분석에 한한다. OCR은 원본 RGB 크롭을 사용한다.

ocr_region_plans는 새로 추가한 4번째 출력이다. 기존 0~2번 출력의 의미는 유지한다.
이 출력의 각 항목을 MangaOCRAdaptive.region_plan_json에 연결해 품질 검사 실패 전부터
확인된 행을 읽는다. 계획은 크기와 행 연속성을 검증하며 전체 크롭을 빈틈·중복 없이 분할한다.
명시된 계획은 line_split=True와 auto/horizontal 방향을 요구한다. 잘못된 계획은 모델 호출 전에
중단한다. 계획이 비어 있는 기존·수동 경로는 종전 OCR 계획을 사용한다.
수집 단계에서도 OCR 진단의 계획과 명세를 대조하므로 연결 누락이나 목록 순서 불일치는 번역 전에 중단한다.

정리된 manifest_json을 OCR 수집과 MangaInpaintPlan.regions_json 양쪽에 전달한다.
따라서 번역·제거·식자가 같은 논리 영역을 사용한다. OCR 여백과 edit_margin은 단·인접 문단의
소유 경계에서 제한하며 경계를 넘어 다시 겹치지 않는다. RF-DETR 원문 마스크 경로와 실제
글자 알파 충돌·말풍선·최소 크기 검사는 유지한다. 임의 번역 축약이나 충돌 검사 해제는 없다.

JSON에는 layout_refinement, layout_sources, layout_column, ocr_region_plan과 영역별 OCR 진단을
남긴다. 새 ID는 c1p1처럼 단·문단 기준으로 정한다. 과거 r3 같은 ID에 수동 식자 옵션을 지정했다면
새 OCR JSON의 ID에 맞춰 검토해야 한다. 기존 저장 그래프의 기본값은 False이고 수동 09도 False다.
새 커스텀 노드를 추가하지 않았다. 새 소켓과 연결을 적용하려면 새 08을 다시 불러온다.

## 확인한 범위

제공된 1060×1500 원본과 15개 원문 영역으로 픽셀 계획을 실행했다. 4개 단 경계
[0,108,422,746,1060], 24개 논리 영역, 90개 초기 OCR 행 입력, 영역당 최대 8개로 정리됐다.
OCR 크롭 간 겹침과 식자 edit 프레임 간 겹침은 모두 0픽셀이다. 모든 크롭이 원본 RGB와 같고,
각 행 입력을 이어 붙이면 해당 크롭을 정확히 재구성한다. 첨부 이미지·원문 JSON은 저장소에
포함하지 않았다. 숫자는 해당 입력의 분석 결과이며 다른 지면에 그대로 적용하는 좌표가 아니다.

합성 다단 지면의 회귀 검사는 중복 검출의 단별 소유, 밝은 보조 번호 보존, 픽셀 재구성,
여백 제한, 실패 전 행 OCR, 수집 단계 ID 일치, 수동/모호한 입력 유지, 잘못된 계획의 모델 호출
차단, 08/09의 명세 연결을 검사한다. 모델 응답은 테스트 대역이다.

실제 RF-DETR/Hayai/vLLM/Qwen GPU 재실행은 여기서 하지 않았다. 잘못된 OCR 단어까지 고쳤다거나
실제 최종 이미지 저장 성공을 확인했다고 주장하지 않는다. 자동 검출이 계속 실패하던 별도 표지도
이 수정의 해결 대상이 아니다. 입력 분할 후에도 틀린 원문·최소 크기 부족이 남으면 새 OCR JSON과
원본 입력 미리보기를 기준으로 확인한다.
